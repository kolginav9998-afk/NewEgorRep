В старой рабочей таблице заказ определяется не одинаковым значением «№ заказа» на всех его строках.
Пользователь нумерует позиции внутри каждого заказа заново с 1.
Пример:
`1, 2, 3, 4, 5` — это один заказ.
Следующая строка с `1` означает начало нового заказа:
`1, 2, 3, 4, 5 | 1, 2, 3 | 1, 2, 3, 4`
= три разных заказа.
Поэтому визуальная граница должна ставиться перед каждой новой исходной строкой заказа, где пользовательская нумерация снова начинается с 1, кроме самого первого блока.
Делать заметную горизонтальную линию по всей ширине таблицы `A:AB`.
Не считать дочерние строки `Ещё поступление`, частичные приходы и автоматически созданные строки новым заказом. Они должны оставаться внутри визуального блока того заказа, к которому относятся.
Если текущая архитектура хранит внутренний `OrderLineID` / parent ID / другой стабильный идентификатор, использовать его для того, чтобы дочерние строки оставались с родителем, но сам момент начала нового пользовательского заказа определяется именно сбросом видимой нумерации на `1`.
Пример ожидаемого отображения:

```
1  Товар A
2  Товар B
3  Товар C
   дополнительное поступление товара C
4  Товар D
5  Товар E
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
1  Товар F
2  Товар G
3  Товар H
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
1  Товар I
2  Товар J
```

Разделитель должен сохраняться/перестраиваться после `Ещё поступление`, проведения, исправления, вставки строк, сохранения и повторного открытия.
Добавить структурный/GUI-тест именно на последовательность:
`1,2,3,4,5,1,2,3,1,2,3,4`
и проверить, что получено ровно 3 визуальных блока заказов и две внутренние разделительные линии.
