## ПРИВЯЗКА К ВЫДАЧЕ

Возврат должен ссылаться на конкретную проведённую выдачу.

Не определять источник только через:

`EI + получатель + количество`.

Использовать стабильный системный идентификатор выдачи Phase 2.

Физический номер строки — только подсказка.

После вставки строк связь должна восстанавливаться по ключу.

## КОЛИЧЕСТВО, ДОСТУПНОЕ К ВОЗВРАТУ

Для конкретной выдачи:

`доступно к возврату = количество проведённой выдачи - сумма действующих возвратов этой выдачи`

Пример:

выдали 10.

Вернули 3.

Потом вернули 2.

Осталось можно вернуть:

5.

Попытка вернуть 6 должна блокироваться.

## НЕСКОЛЬКО ВЫДАЧ ОДНОГО EI

Пример:

EI-1:

* выдача №1 → Иванову 5;
* выдача №2 → Петрову 3.

Возврат по выдаче №1 не должен уменьшать обязательство выдачи №2.

Контроль возврата ведётся по конкретной выдаче.

## ПОЛНЫЙ ВОЗВРАТ

Если возвращено всё количество конкретной выдачи:

статус возврата/выдачи служебно считается закрытым по возвратам.

Саму строку выдачи НЕ удалять и не менять её историческое количество.

## ЧАСТИЧНЫЙ ВОЗВРАТ

Допускаются:

* 10 → вернуть 3;
* затем ещё 2;
* затем оставшиеся 5.

Каждый возврат:

* отдельная строка;
* отдельная операция;
* отдельный № возврата;
* тот же EI.

## EI

Возврат всегда относится к существующему EI.

Запрещено:

* создавать новый EI;
* автоматически выбирать «похожий» EI;
* заменять EI другим при нулевом остатке.

Если EI исходной выдачи существует в реестре, возврат восстанавливает его остаток.

Даже если текущий остаток EI = 0, возврат разрешён.

## ПОЛУЧАТЕЛЬ

`I От кого возвращено` должен соответствовать получателю исходной выдачи.

При обычном возврате подставлять автоматически.

Если пользователь пытается изменить получателя на другого — блокировать либо требовать отдельного будущего сценария передачи.

На Phase 4 обычный возврат означает:

возврат от того же получателя, которому была сделана исходная выдача.

## МЕСТО ХРАНЕНИЯ

По умолчанию предлагать текущее место EI из `Наличие`.

Если пользователь меняет место при возврате:

* это становится новым текущим местом EI;
* изменение места выполняется в той же атомарной операции возврата.

Не создавать отдельное перемещение.

## КНОПКИ `Возврат`

Минимум:

`Найти выдачу`

`Проверить`

`Провести`

`Исправить`

`Удалить`

`Очистить`

По возможности обычный сценарий:

№ выдачи / EI → автоматически заполнить данные → количество → дата → Провести.

Не заставлять пользователя запускать макросы через меню.

## НОМЕР ВОЗВРАТА

Системный, монотонный, не переиспользуется.

Если текущая архитектура позволяет использовать общий `NEXT_NO` без неоднозначности — сначала проверить существующие правила.

Если нужен отдельный счётчик `NEXT_RETURN_NO`, вынести это как архитектурное решение в отчёт и реализовать наиболее безопасный вариант, не нарушающий Phase 1–3.

Номер, который мог попасть в журнал/документ до recovery/abandon, не переиспользовать.

## ИСПРАВЛЕНИЕ ВОЗВРАТА

Проведённую строку вручную не менять.

`Исправить` = одна составная операция:

`RETURN_FIX`

Пример:

выдали 10;

вернули 3;

исправляем возврат 3 → 4.

Остаток EI увеличивается ещё на 1.

Исправляем 3 → 2:

остаток уменьшается на 1.

Но после изменения:

`сумма действующих возвратов этой выдачи <= количество действующей выдачи`

всегда должна выполняться.

## СТОРНО ВОЗВРАТА

`Удалить` = сторно:

`RETURN_DEL`

Строка остаётся как история.

№ возврата не переиспользуется.

Остаток EI уменьшается на количество сторнированного возврата.

Но операция должна быть запрещена, если после сторно остаток EI станет меньше уже последующих зависимых списаний.

Пример:

остаток был 0;

вернули 5 → остаток 5;

после этого выдали эти 5 другому человеку;

сторнировать исходный возврат нельзя, потому что остаток стал бы отрицательным.

## ИЗМЕНЕНИЕ ИСХОДНОЙ ВЫДАЧИ

Phase 2 умеет `ISSUE_FIX` и `ISSUE_DEL`.

Теперь они должны учитывать возвраты.

### ISSUE_FIX

Нельзя уменьшить количество исходной выдачи ниже уже возвращённого по ней количества.

Пример:

выдали 10;

вернули 7;

исправить исходную выдачу на 5 — запрещено.

На 7 — допустимо.

На 12 — допустимо при наличии складского остатка для дополнительного списания.

### ISSUE_DEL

Если по выдаче существуют действующие возвраты:

сторно выдачи должно быть запрещено до сторно связанных возвратов.

Не создавать автоматически обратные возвраты без отдельного решения.
