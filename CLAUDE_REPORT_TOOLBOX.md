## 0. Итог

- **`WMS_TOOLBOX/`** собирается `tools/build_toolbox.py` из текстовых исходников (`src/toolbox/*.bas`, `src/toolbox/scripts/`). Бинарные книги в Git не хранятся (D-009).
- **9 книг инструментов:** INVENTORY, ANALYTICS, MANAGER, SEARCH, DOCTOR, LABELS, DOCS, ARCHIVE, IMPORTER.
- **Launcher** `WMS_TOOLBOX.ods`: открывает инструменты по относительным путям, показывает последний снимок и пакеты, запускает проверку перед сменой, сверку названий и соответствие. Для работы WMS не нужен.
- **Скрипты (python3, только стандартная библиотека):**
  - RECONCILE — `reconcile/wms_reconcile.py`, сверка старых названий и соответствие, подтверждённое человеком;
  - BACKUP + HEALTHCHECK — `backup/wms_backup.py`, `backup/wms_healthcheck.py`;
  - адаптер термопринтера — `labels/tspl_labels.py` (TSPL).
- **Безопасность:** ни один инструмент не открывает рабочую книгу WMS.
  - Снимок проверяется по SHA-256 до чтения; изменённый снимок не используется.
  - Изменения склада уходят только пакетами `WMS-BATCH-1`; WMS проверяет их целиком и проводит своими операциями. Пакеты INVENTORY и IMPORTER проверены загрузчиком WMS в тестах.
- **Тесты** (`tests/run_toolbox.py`, фиксированная фикстура снимка, один прогон на одном коде — `TEST_REPORT.md`): K01–K13, **45 PASS / 0 FAIL / 0 SKIP**; компиляция всех модулей всех книг (`tools/tb_compile_check.py`) — OK. Ядро WMS в M4 не менялось, поэтому полная регрессия этапов не повторялась (задание §8); пакеты INVENTORY и IMPORTER проведены самой WMS в тестах.

## 2. Устройство

- **Общий модуль `TbCommon`** в каждой книге:
  - папки по относительным путям;
  - выбор последнего снимка и проверка его manifest (формат, размер и SHA-256 каждого файла);
  - загрузка таблицы снимка на скрытый лист штатным CSV-фильтром (числа и даты — значения, коды и артикулы — текст);
  - запись пакета `WMS-BATCH-1`.
- **Сообщения:** кнопки показывают итог окном. В тестах — записываются (`TbTestAuto`), окно не показывается.
- **Ошибки:** у главной функции каждого инструмента есть обработчик. Внутренняя ошибка возвращает «ERR: внутренняя ошибка инструмента … (строка N)», а не пустой результат.
- **Ловушки LibreOffice Basic, найденные в M4** (записаны в `FINAL_HANDOFF.md`):
  - `InStrRev`, `Round` и `Filter` есть только в режиме VBA (заменены на `TbInStrRev`, `Int(x*1000+0,5)/1000` и цикл);
  - `InStr` по умолчанию не различает регистр: «ОШИБК» находит «ошибок» (итог проверки перед сменой сравнивается с «ИТОГ: ошибок 0,» при `InStr(1, …, 0)`);
  - путь файла для скрипта берётся из системного пути (`ConvertFromURL`), а не из URL: в URL кириллица может быть закодирована;
  - `DateSerial` не принимает месяц вне 1…12 (`TbMonthStart`);
  - модули компилируются по отдельности: общая функция должна быть в общем модуле книги;
  - `IIf` вычисляет обе ветви;
  - `Write` и `Fix` нельзя использовать как метку или параметр.
- **Компиляция:**
  - `tools/tb_compile_check.py` вызывает функцию каждого модуля каждой книги в окне (Xvfb) и перехватывает окно ошибки компилятора;
  - `tests/run_toolbox.py` K01 проверяет, что каждая кнопка привязана к процедуре своей книги.
- **Writer:** WMS_DOCS пишет ODT через LibreOffice Writer. В контейнере его не было — пакет установлен для тестов. Проверка перед сменой предупреждает, если Writer не установлен.
