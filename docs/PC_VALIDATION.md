# Проверка складского ПК и принтера перед вводом WMS

Автоматический пакет проверки: каждая проверка выполняется скриптом, вручную нужно только посмотреть на напечатанную этикетку. Рабочая папка WMS при этом не открывается и не меняется: все тестовые книги и журналы создаются в папке результатов проверки.

## 1. Что нужно

- ПК с Ubuntu 22.04 или 24.04 (подойдёт и другой Linux на базе Debian), права `sudo`, интернет для установки пакетов.
- Принтер этикеток, подключённый к ПК (USB).
- Около 2 ГБ свободного места и 15 минут (полная проверка — около 45 минут).
- На время проверки WMS лучше закрыть: проверка сильно загружает ПК.

## 2. Установить программы (один раз)

```
sudo apt update
sudo apt install -y libreoffice-calc libreoffice-writer python3-uno xvfb cups fonts-dejavu fonts-liberation git
sudo locale-gen ru_RU.UTF-8
```

## 3. Получить WMS

```
cd ~
git clone -b claude/festive-lamport-l4f8f1 https://github.com/kolginav9998-afk/NewEgorRep.git WMS_SRC
cd WMS_SRC
```

Без git: на GitHub откройте ветку `claude/festive-lamport-l4f8f1` → «Code» → «Download ZIP», распакуйте в `~/WMS_SRC` и выполните `cd ~/WMS_SRC`.

## 4. Автоматическая проверка ПК

```
python3 tools/pc_check.py
```

Скрипт выполняет:
1. **Проверку среды** — система, Python, LibreOffice (версия), Python-UNO, Writer, шрифты с кириллицей, локаль, свободное место, Xvfb, CUPS и принтеры, USB-принтеры.
2. **Компиляцию** всех модулей WMS и всех книг инструментов — в невидимом дисплее, на экране ничего не появится.
3. **Тесты на этом ПК** (около 10–15 минут):
   - книга-кандидат;
   - перенос старого склада;
   - операции ядра (Final Core);
   - все инструменты;
   - сквозной тест рабочего дня: выпуск → перенос → заказ и приход → иной приход → пополнение детали → перемещение → выдача → возврат → списание → инвентаризация → сохранение → повторное открытие → копии → снимок → инструменты.

Полная проверка — ещё все этапы 1–5 и проверки окон (около 45 минут):

```
python3 tools/pc_check.py --full
```

Только среда (несколько секунд):

```
python3 tools/pc_check.py --env-only
```

**Результат** появится на экране и в `pc_check_results/<дата-время>/PC_CHECK_REPORT.md`. Рядом лежит архив `pc_check_results/<дата-время>.tar.gz`: в нём отчёты и журналы тестов, книг нет. Код выхода: 0 — всё прошло, 1 — есть провалы, 2 — проверка не запустилась.

## 5. Проверка принтера этикеток

Какие принтеры видит система:

```
python3 tools/printer_check.py
```

**Принтер с драйвером** — есть в списке CUPS (добавляется в «Параметры → Принтеры» или на `http://localhost:631`). Печатаются тестовые этикетки 58×40 мм тем же путём, что кнопка «Печать» в WMS_LABELS:

```
python3 tools/printer_check.py --cups ИМЯ_ПРИНТЕРА
```

**Принтер без драйвера**, понимающий команды TSPL (TSC, Xprinter, Gprinter и совместимые):

```
python3 tools/printer_check.py --tspl /dev/usb/lp0
```

- **Другой размер этикетки** — `--size 58x30`.
- **Принтер 300 dpi** — `--dpmm 12`.
- **Носитель в CUPS** — `--media Custom.58x40mm`.
- **Посмотреть макет без печати** — `--pdf-only`.
- **Нет прав на `/dev/usb/lp0`** — выполните `sudo usermod -aG lp $USER`, выйдите из системы и войдите снова.

После печати скрипт спросит, верно ли напечатано: ЕИ крупно, наименование, артикул, место, штрихкод читается сканером. Ответ записывается в `pc_check_results/printer_check.txt` и в последний `PC_CHECK_REPORT.md`.

## 6. Что прислать разработчику

- `pc_check_results/<дата-время>.tar.gz`, или хотя бы `PC_CHECK_REPORT.md`;
- `pc_check_results/printer_check.txt`;
- по возможности — фото напечатанной тестовой этикетки и название (модель) принтера.

## 7. После проверки

1. Разработчик по отчёту подтверждает ПК или присылает исправление, после него проверка повторяется.
2. Перенос настоящих остатков — только с вашим файлом остатков (`tools/migrate.py`: проверка → перенос в копию → сверка → рабочая книга `WMS_PROD.ods`; подробно — `CLAUDE_REPORT_MIGRATION_CANDIDATE.md`, раздел 1).
3. Выпуск на этом ПК собирается командой `python3 tools/build_release.py ~/WMS_RELEASE`: книга-кандидат, `WMS_TOOLBOX`, документы, инструменты переноса.
4. Папку `WMS_TOOLBOX` положите рядом с `WMS_PROD.ods`. Работа кладовщика описана в `docs/OPERATOR_GUIDE.md`, этот текст есть и на листе «Справка» в самой книге.
