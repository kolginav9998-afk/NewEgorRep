>
> После этого основное ядро должно быть заморожено.

> **Перемещение EI**
>
> `MOVE`
>
> EI → новое место → дата → причина/комментарий.
>
> Количество не меняется.
>
> Старое и новое место в журнале.

> Запрет тихого изменения места.

> **Списание**
>
> `WRITE_OFF`
>
> EI → количество → дата → причина → комментарий.
>
> Остаток уменьшается.
>
> Нельзя уйти ниже нуля.
>
> Это не обычная выдача человеку.
>
> Исправление и сторно — по тем же принципам журнала.

>
> `INV_ADJ`
>

> - отрицательные остатки;
> - orphan EI;
> - повреждённые ссылки;
> - счётчики;
> - дубли;
> - конфликт артикула;
> - duplicate rows;
> - защиты;
> - версии схемы;
> - backup freshness;
> - расхождения snapshot/journal.
>
> Выход: понятный отчёт + рекомендуемый repair plan.
>
> Никаких автоматических опасных исправлений.
>
> **WMS_RECONCILE**
>
> Полностью офлайн.
>
> Для старых выдач/названий, введённых руками:
>
> - нормализация строки;
> - точное совпадение;
> - артикул;
> - fuzzy matching;
> - top-5 EI кандидатов;
> - confidence;
> - пользователь подтверждает соответствие.
>
> Ничего не проводить автоматически по одной только fuzzy-оценке.
>
> Сформировать mapping/import report.
>
> Для этого не нужен тяжёлый LLM, если RapidFuzz/нормализация дают более детерминированный результат.
>
> **WMS_LABELS**
>
> Источник — snapshot/WMS export.
>
> Этикетка:
>
> - EI крупно;
> - наименование;
> - артикул;
> - место;
> - опционально QR/barcode без обязательных внешних шрифтов.
>
> Настройки размеров этикетки и полей.
>
> Базовая печать через системный принтер LibreOffice/CUPS.
>
> Не привязывать ядро WMS к конкретному драйверу.
>
> Отдельно оставить адаптер для прямого протокола принтера после теста реального оборудования.
>
> **WMS_DOCS**
>
> Генератор ODT:
>
> - акт передачи;
> - передача деталей;
> - передача сторонней организации;
> - выбранные движения/позиции;
> - номер документа;
> - дата;
> - передал/принял;
> - история созданных документов.
>
> **WMS_ARCHIVE**
>
> Сначала безопасный режим:
>
> - анализ размера;
> - какие периоды можно архивировать;
> - создание проверяемого archive package;
> - hash/manifest;
> - read-only просмотр истории.
>
> Никогда автоматически не удалять историю из PROD.
>
> Если понадобится физическая компактизация рабочей книги — только отдельной подтверждаемой процедурой release/upgrade с тестом восстановления.
>
> **WMS_BACKUP + HEALTHCHECK**
>
> Небольшие offline-скрипты:
>
> - проверить LibreOffice;
> - каталоги WMS;
> - права записи;
> - свободное место;
> - наличие журнала;
> - последнюю backup;
> - версии;
> - целостность файлов;
> - создать дополнительную backup-копию.
>
> **WMS_IMPORTER**
>
> Staging для массового ввода из CSV/ODS:
>
> - preview;
> - mapping колонок;
> - validation;
> - duplicates;
> - только потом batch для WMS.
>
> Не писать напрямую в служебные листы.
>
