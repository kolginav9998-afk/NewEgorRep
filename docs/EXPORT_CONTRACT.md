# Контракт WMS ↔ инструменты: снимок WMS-SNAPSHOT-1 и пакет WMS-BATCH-1

**Версия контракта:** 1 (26.09.2026, ядро `0.6.0-final-core`, схема `_SYS` `WMS-SYS-3`).
**Где реализовано:** `src/basic/WmsExport.bas` (кнопки «Экспорт для инструментов» и «Загрузить пакет» на листе «Главная»); проверка — `tests/run_final_core.py` Y20–Y22.

## 1. Принцип

- Боевая книга (`WMS_PROD.ods`) — единственное место, где меняется склад. **Инструменты никогда не открывают её на запись.**
- WMS → инструменты: **снимок** — неизменяемая папка файлов вне книги, по кнопке «Экспорт для инструментов». Аналитика, отчёты, поиск, Doctor, архив, этикетки, акты читают снимок, а не живую WMS.
- Инструменты → WMS: **пакет** — файл строк для листа ввода WMS. WMS проверяет пакет целиком, загружает строки в колонки ввода и по подтверждению проводит их своими обычными операциями (каждая строка — своя операция со всеми проверками, журналом, восстановлением). Служебные листы пакет не трогает.

## 2. Снимок WMS-SNAPSHOT-1

**Папка:** `<папка книги>/WMS_Export/WMS_SNAPSHOT_<ГГГГММДД-ЧЧММСС>_seq<LAST_SEQ>/` (при совпадении имени — суффикс `_2`, `_3` …). Папка появляется под своим именем только целиком (пишется во временную `.<имя>.part/`, затем переименовывается). Снимок создаётся только в рабочем состоянии WMS (не при блокировке). Книга при экспорте не меняется, в журнал ничего не пишется.

### 2.1 manifest.csv

Строки `ключ;значение…` (первая строка — `key;value`):

| Ключ | Значение |
|---|---|
| `format` | `WMS-SNAPSHOT-1` |
| `product_version`, `core_version`, `schema` | версия продукта, ядра, схема `_SYS` (`WMS-SYS-3`) |
| `instance_id`, `mode` | экземпляр WMS, `PROD` / `TEST` |
| `created` | время снимка `ГГГГ-ММ-ДДTчч:мм:сс` |
| `book` | путь книги |
| `last_seq`, `journal_pos` | последняя операция, отражённая в книге, и позиция журнала |
| `next_ei`, `next_issue`, `next_return`, `next_line`, `next_adj` | счётчики |
| `book_modified` | `1` — в книге есть операции после последнего сохранения (они есть и в журнале) |
| `file;<путь>;<строк>;<байт>;<SHA-256>` | каждый файл снимка; строк данных (−1 для журнала) |

Инструмент обязан проверить `format`, размер и SHA-256 каждого файла; снимок с расхождением не используется.

### 2.2 Таблицы (формат)

UTF-8 без BOM, разделитель `;`, строки через LF, текст с `;`, `"` или переносом — в кавычках `"…"` (кавычка удваивается). **Первая строка — английские ключи колонок; строка k файла (k ≥ 2) — строка k листа книги** (пустые строки листа остаются пустыми строками файла). Числа — с точкой, без разделителей разрядов; даты в колонках дат — `ГГГГ-ММ-ДД`; остальное — текст как в книге.

| Файл | Лист | Колонки (порядок = колонки листа A, B, …) |
|---|---|---|
| `stock.csv` | «Наличие» (строка = номер ЕИ) | `ei`, `name`, `article`, `unit`, `qty`, `place`, `category`, `state`, `source`, `source_type` |
| `orders.csv` | «Заказы» | `order_no`, `name`, `doc_no`, `invoice_no`, `article`, `qty_fact`, `qty_doc`, `qty_ordered`, `unit`, `price`, `amount`, `supplier`, `seller`, `date_received`, `date_doc`, `date_order`, `date_expected`, `buyer`, `category`, `assignee`, `place`, `ei`, `status`, `stock`, `control`, `note`, `lead_days`, `possible_dup` |
| `special.csv` | «Иной приход» | `line_no`, `type`, `event`, `name`, `article`, `qty`, `unit`, `date`, `place`, `category`, `from_who`, `doc`, `old_mark`, `ei`, `bal_before`, `bal_after`, `status`, `control`, `note` |
| `issues.csv` | «Выдачи» | `issue_no`, `doc_no`, `name`, `article`, `qty`, `qty_pct`, `unit`, `date`, `recipient`, `place`, `category`, `ei`, `returned_legacy`, `returned_pct_legacy`, `note`, `bal_before`, `bal_after`, `status` |
| `returns.csv` | «Возврат» | `return_no`, `issue_no`, `ei`, `name`, `article`, `qty`, `unit`, `date`, `from_who`, `place`, `category`, `bal_before`, `bal_after`, `status`, `note` |
| `adjustments.csv` | «Корректировки» | `adj_no`, `kind`, `ei`, `name`, `article`, `unit`, `qty`, `fact`, `book`, `place_to`, `date`, `reason`, `place_from`, `bal_before`, `bal_after`, `diff`, `status`, `batch`, `note` |
| `recipients.csv` | «Получатели» | `short`, `full` |
| `service/_ORD.csv`, `_RCV`, `_SPR`, `_ART`, `_RET`, `_ISS`, `_ADJ`, `_SYS` | служебные таблицы | заголовок — как в книге; **внутренние данные схемы `WMS-SYS-3`** — только для WMS_DOCTOR, могут меняться со схемой |
| `journal/WMS_journal_ГГГГ-ММ.csv` | внешний журнал | копия всех файлов; книга отражает журнал до `last_seq` (строки после — хвост, которого нет в книге) |

### 2.3 Как читать движения (для аналитики, поиска, истории ЕИ)

Проведённая строка — строка с номером в первой колонке (кроме `stock`) и без отметки `КОПИЯ` в колонке контроля. Статус: `Проведено`, `Проведено (исправлено)`, `Удалено (сторно)` (у листа «Иной приход» — `Проведено: …` / `Проведено (исправлено): …`). Исправление и сторно видны как итоговое состояние строки; полная хронология — в журнале.

| Движение | Откуда | Количество (знак для остатка) | Дата | Действует |
|---|---|---|---|---|
| приход по заказу | `orders.csv`, строки с `ei` | `qty_fact` (+) | `date_received` | запись `_RCV` этого ЕИ `LIVE` (`service/_RCV.csv`, колонка «Состояние») |
| иной приход | `special.csv` с `line_no` | `qty` (+) | `date` | `status` ≠ `Удалено (сторно)` |
| выдача | `issues.csv` с `issue_no` | `qty` (−) | `date` | `status` начинается с `Проведено` |
| возврат | `returns.csv` с `return_no` | `qty` (+) | `date` | `status` ≠ `Удалено (сторно)` |
| перемещение | `adjustments.csv`, `kind` = `Перемещение` | 0; места `place_from` → `place_to` | `date` | `status` ≠ `Удалено (сторно)` |
| списание | `adjustments.csv`, `kind` = `Списание` | `diff` (−) | `date` | то же |
| инвентаризация | `adjustments.csv`, `kind` = `Инвентаризация` | `diff` (±); `book` → `fact` | `date` | то же |

Для каждого ЕИ: `stock.qty` = сумма действующих движений (для ЕИ начального реестра / переноса — плюс начальный остаток).

## 3. Пакет WMS-BATCH-1

CSV UTF-8 (BOM допускается), разделитель `;`, кавычки как в §2.2. Сначала строки метаданных `#ключ;значение`, затем строка ключей колонок, затем строки данных:

```
#WMS-BATCH-1
#id;INV-20260921-001
#target;Корректировки
#source;WMS_INVENTORY
#snapshot;WMS_SNAPSHOT_20260921-101500_seq1234
kind;ei;fact;book;date;reason
Инвентаризация;ЕИ-00000050;5;1;21.09.2026;инвентаризация 21.09
```

| Метаданные | Правило |
|---|---|
| `#WMS-BATCH-1` | обязательна (формат) |
| `#id` | обязателен: латинские буквы, цифры, `-`, `_`, `.`; до 60 символов. **Один пакет загружается один раз** (отметка — колонка R «Пакет» листа «Корректировки» или `[пакет <id>]` в комментарии «Иной приход» / «Заказы»; повторная загрузка — отказ) |
| `#target` | `Корректировки`, `Иной приход` или `Заказы` |
| `#source`, `#snapshot` | инструмент и снимок, на котором он работал (для истории) |
| `#shared;yes` | «Иной приход»: строки одного типа — одно поступление (один № OFF/PROD/DET/OLD/OTH) |

Колонки ввода (ключи):

| Лист | Ключи |
|---|---|
| «Корректировки» | `kind` (Перемещение / Списание / Инвентаризация), `ei`, `qty` (списание), `fact` (инвентаризация: фактический остаток), `book` (инвентаризация: учётный остаток снимка), `place` (новое место), `date`, `reason`, `note` |
| «Иной приход» | `type`, `event`, `name`, `article`, `qty`, `unit`, `date`, `place`, `category`, `from_who`, `doc`, `old_mark`, `note` |
| «Заказы» | `order_no`, `name`, `doc_no`, `invoice_no`, `article`, `qty_fact`, `qty_doc`, `qty_ordered`, `unit`, `price`, `amount`, `supplier`, `seller`, `date_received`, `date_doc`, `date_order`, `date_expected`, `buyer`, `category`, `assignee`, `place`, `note`, `lead_days` |

Значения — как их вводит пользователь: даты `дд.мм.гггг` или `ГГГГ-ММ-ДД` (колонки `date…`), количества с запятой или точкой и без лишних нулей (`1,5`, не `1,500` — такое WMS считает неоднозначным), ЕИ в любом принятом виде (`12`, `ЕИ-12`, `ЕИ-00000012`).

Проверка целиком (одна ошибка — не загружается ничего): формат, `#id`, лист, колонки только из списка и без повторов, число полей каждой строки = числу колонок, нет пустых строк, нет формул (`=` в начале), не больше 5000 строк. Затем строки записываются ниже последней занятой строки листа (только колонки ввода; одно действие Ctrl+Z убирает весь загруженный блок, пока он не проведён) и WMS спрашивает «Провести эти строки сейчас?». «Да» — каждая строка проводится обычной операцией листа; строка с ошибкой не проводится (причина — в «Контроль»), остальные проводятся; системная ошибка WMS останавливает обработку. «Нет» — строки остаются непроведёнными для просмотра.

**Инвентаризация по снимку:** `book` — учётный остаток ЕИ в снимке. Если к проведению остаток ЕИ изменился (после снимка были движения), строка не проводится: «учётный остаток изменился … пересчитайте заново» — корректировка никогда не считается от другого остатка, чем тот, с которым сравнивали пересчёт.

## 4. Совместимость

Инструмент проверяет `format` (`WMS-SNAPSHOT-1`) и `schema`. Следующие версии контракта только добавляют колонки справа и файлы; удаление или смена смысла колонки — новый `format` (`WMS-SNAPSHOT-2`) и новая версия инструментов.
