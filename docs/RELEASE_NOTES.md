# WMS — примечания к выпуску

## 1.0.2 — этикетки пачкой, акты, отчёт дня, метизы, категории, серийные детали

**Версии:** продукт `1.0.2`, ядро `1.0.2`, схема служебных данных `WMS-SYS-5` (как 1.0.0), журнал `J1` без изменений, **новых операций
журнала нет** (серийные детали — цепочка прежних «Разделение» и «Свойства ЕИ»; номер акта — прежний `ISSUE_DOC`), контракт снимка `1.1`.
Обновление из рабочей книги 1.0.0 / 1.0.1 (и из 0.7.x) — мастером `WMS_UPGRADE.ods`: новая папка, сверка каждой ячейки, старая книга
и журнал не меняются (откат). Новые листы — ваши: без защиты, в журнал не пишут.

### Этикетки (8 замечаний пользователя от 26.10.2026)
- **Целый заказ сразу.** «Этикетка» на нескольких выделенных строках открывает окно: для **каждой позиции** своё число этикеток
  (1 — одна на всю поставку; 0 — без этикетки). Кнопка **«По количеству единиц»** — столько этикеток, сколько единиц (100 красок —
  100 этикеток; не больше 200 на позицию). Позиций больше 18 — по страницам. Не помещается на страницу «Печать» — отказ до печати.
- **Упаковка кратно.** Одна этикетка на поставку, а выдают по одной: вторая строка этикетки «Выдача по 1 шт · в 1 уп. — 10 шт» (из
  фасовки ЕИ или из новой колонки **«В упаковке, шт»** листа «Номенклатура»).
- **Артикул на этикетке — только у категории «Детали»**: «Арт.: …».
- **Детали с серийными номерами — «Серийные…»** на «Наличии»: артикул один, номера разные; деталь с номером становится своим ЕИ
  (тот же артикул, место, срок годности и примечание) со своей этикеткой «Арт.: … · S/N: …». Повтор номера, номер другого ЕИ, ЕИ
  с фасовкой и дробный остаток — отказ до записи.

### Акты
- **«Акт…» на «Выдачах»** по выделенным выдачам одного получателя: документ Writer «АКТ № N — приема-передачи оборудования» (в офис)
  или «выдачи оборудования» (получателю) в вашем образце: город и дата, таблица № п/п · Наименование · Артикул · Количество ·
  Ед изм, подписи. Номер — следующий по реестру **«Акты»**, он же записывается в «№ документа выдачи». «Повторить акт» — тот же номер.

### Отчёт дня
- Лист **«Отчёт дня»**, кнопка «Подготовить отчёт»: документ Writer в вашем шаблоне — дата, подпись, «1. Завершено сегодня», «2. Задачи
  на <следующий рабочий день>», «3. В процессе», «4. Контроль данных». Цифры берутся из журнала: машины, приёмка (позиции, количество,
  коды ЕИ, адресное хранение), иной приход по источникам, выдачи, акты, исправления. Выдачи вчерашнего дня, внесённые сегодня, —
  «Оцифровка выдач за <дата>» отдельно от выдач сегодняшним числом; график 5/2 — выходные пропускаются. Своё (пропуска, разговоры
  с руководителем) вписывается в списки листа.

### Метизы и категории
- **«Метизы»** — справочник из «Наличия» по названию: тип, размер (М8×30), стандарт (DIN, ГОСТ, ISO), класс (8.8, А2), покрытие,
  остаток, места; поиск по любым словам; порядок — тип, диаметр, длина. **«Категории»** — подсказки: пустая «Категория» на «Заказах»
  и «Ином приходе» заполняется по названию; своя категория подсказкой не заменяется, список — выпадающий, но допускает любое слово.

### Обновление
- Мастер принимает рабочую книгу **1.0.0, 1.0.1** и 0.7.x. Данные не меняются; добавлены листы «Акты», «Отчёт дня», «Категории»,
  «Метизы», колонка «В упаковке, шт» («Номенклатура», R; подсказка листа сдвинута в S), список категорий, кнопки «Серийные…» и «Акт…».
- Проверка локальности: `python3 tools/offline_audit.py <папка>` — сетевых возможностей в книгах, макросах и программах не находит.

## 1.0.1 — этикетка 40×30, «Пришло / Осталось», комплекты из ЕИ

**Версии:** продукт `1.0.1`, ядро `1.0.1`, схема служебных данных `WMS-SYS-5` (как 1.0.0), журнал `J1` без изменений, контракт
снимка `1.1`. Новых операций журнала нет. Обновление из рабочей книги 1.0.0 (и из 0.7.x) — мастером `WMS_UPGRADE.ods`: новая
папка, сверка каждой ячейки, старая книга не меняется (откат).

### Этикетка
- **40×30 мм под термопринтер** (Xprinter XP-420B и подобные, 203 dpi): номер ЕИ крупно, **полное наименование** — шрифт сам
  уменьшается, пока название не уместится целиком (очень длинное — до 5 пт, затем «…»), **«Ед. изм.: …»** и штрихкод Code 128 в
  своей полосе внизу. Артикула и места на этикетке больше нет. Поля 1 мм, штрихи — целое число точек принтера.
- **Исправлено:** в 1.0.0 штрихи штрихкода рисовались вверху этикетки, поверх номера ЕИ (LibreOffice терял положение фигуры,
  заданное до её добавления на лист). Теперь штрихкод всегда в своей полосе; тест проверяет каждый штрих каждой этикетки.
- То же — в инструменте `WMS_LABELS` (набор инструментов, WMS_TOOLBOX `1.1.4`): по умолчанию 40×30, артикул и место — только
  если включить их в «Настройках».

### «Наличие»
- Рядом друг с другом: **«Пришло»** (приход по заказу, иной приход, перенос из старой таблицы, разделение, комплект) и
  **«Осталось»** (остаток).
- Дальше — сведения о товаре: **кому назначено**, **поставщик / откуда пришло**, дата и документ прихода, № заказа, фасовка,
  серийный / инвентарный №, «годен до», резерв.
- Сведения обновляются сами при открытии листа после операции — только сдвинувшиеся строки (0,1 с даже на 20 000 ЕИ), целиком —
  при первом открытии после обновления, в начале дня на небольшом складе и кнопкой **«Обновить сведения»** (например, после
  правки «Кому назначено» на «Заказах»). Проведение их не пишет и не замедляется.

### Комплекты из конкретных ЕИ
- В составе на листе «Комплекты» вместо артикула можно написать **номер ЕИ** («ЕИ-427»): эта позиция берётся только с этого ЕИ.
- **«Собрать из ЕИ…»** на «Наличии»: выделите строки нужных ЕИ, нажмите кнопку, укажите название, сколько собрать, сколько
  каждого ЕИ на 1 комплект, место — комплект собран (та же операция сборки, «Удалить» разбирает). Состав можно сразу записать на
  «Комплекты», чтобы потом собирать его кнопкой «Собрать комплект…».

### Вид
- **Сетка ячеек видна** на всех листах, и на цветных строках тоже (WMS включает настройку LibreOffice «линии сетки на цветных
  ячейках»; её видно на «Обслуживании» → «Советы LibreOffice»).

### Обновление
- Мастер принимает рабочую книгу **1.0** (и по-прежнему 0.7.x), сам находит её в папке прежнего выпуска; папка состояния WMS
  (`WMS_State`: копия на флешку, напоминания), фото и документы переносятся в новую папку.
- Первое открытие «Наличия» после обновления заполняет новые колонки — на большом складе это несколько секунд, один раз.

## 1.0.0 — WMS PRIME 1.0: окончательная версия

**Версии:** продукт `1.0.0`, ядро `1.0.0`, схема служебных данных `WMS-SYS-5` (как в 0.8), журнал `J1` (новое поле `CH` —
контрольная цепочка; новые операции `SPLIT`, `SUP_RET`, `KIT_BUILD`, `KIT_DEL`, `EI_PROP`, `ISSUE_DOC`, `MONTH_CLOSE`,
`MONTH_OPEN`), контракт снимка `1.1`.

**Ваши данные 0.7.2 переходят целиком.** Мастер `WMS_UPGRADE.ods` собирает новую книгу из вашей рабочей книги 0.7.2 в новой
папке и сверяет каждую ячейку, каждый ЕИ (номер, наименование, артикул, единица, остаток, место) и журнал побайтно. Старая книга
и её журнал не меняются ни на байт — это откат. Проведение не медленнее 0.7.2 (две библиотеки Basic и экран без перерисовки во
время записи, D-101).

### Ежедневная работа
- **Окна «Выдать…» и «Принять…»**, «Принять всё по заказу», «Повторить», «Выдать» из «Наличия» и карточки ЕИ, «Вернуть
  выделенное» из «на руках»; **несколько выдач разом** — одним документом или каждую отдельно; количество **«всё»** — весь
  остаток без хвостов; горячие клавиши **Ctrl+Shift+P / E / F / W / Q**.
- **Вид:** поля ввода светло-жёлтые, поля WMS серые; цвет кнопки по смыслу; подсказка у каждой колонки; «Главная» — меню;
  закреплённые колонки; «Почему?» — всё, что не так со строкой; даты «ДД.ММ.ГГГГ», без технических кодов.
- **Части и металл:** «Остаток частями» в «Наличии», фасовка по товару и из «Номенклатуры», «пол кан», «1/4 кан», «2 + 1 кан»,
  «Проведено · 1 кан» в строке, «Списать хвосты…», «Фасовка пачкой…», вес метра, обрезки металла.

### Места и карта
- **Разделение ЕИ** (часть — новым ЕИ со своим местом и этикеткой), **карта правится прямо на карте** («Править карту» →
  «Сохранить карту» с проверкой, «Отменить правку»), вместимость мест и слой «Заполненность», «Показать на карте», история места,
  «Куда положить?» с учётом вместимости, **список мест «+1-2-5» / «−1-2-3» и диапазон «1-2-3…5»**, «Одно из мест опустело?»,
  «Переименовать ряд…», **«Маршрут сбора»**.

### Заказы, контроль, отчёты
- **Возврат поставщику**, справочники **«Поставщики»** и **«Номенклатура»**, страница **«Снабжение»** («Ожидаем», «Нужно
  заказать»), «Отменить весь заказ», «Повторить заказ», **акт расхождения**.
- **Причина** каждого исправления и удаления, **«История изменений»**, документы на «Печати» и в PDF: акт списания, накладная на
  выдачу, карточка ЕИ, инвентаризационная опись и сличительная ведомость; **«Пересчитать место…»**.
- **«Отчёты»:** остаток на дату, оборотная ведомость в единицах и рублях, выгрузка движений в CSV (Excel, 1С), **сверка с 1С**,
  **закрытие месяца** (задним числом — только с причиной), отчёт руководителю, расход по получателям, мёртвый груз; деньги на
  складе на «Дашборде», переходы с «Дашборда» и «Внимание» списком.

### Вещи и комплекты
- **Комплекты:** лист «Комплекты», «Выдать комплект…», **«Собрать комплект…»** (составляющие списываются, комплект приходит своим
  ЕИ; «Удалить» разбирает обратно).
- **Этикетка ЕИ со штрихкодом** прямо из WMS, **серийный номер и «годен до»** (поиск по серийному номеру), **инструмент на руки**
  со сроком возврата («Где инструмент»), **резерв** под получателя или объект, **фото позиции** из папки «WMS_Фото».

### Сохранность данных — страница «Обслуживание»
- **«Здоровье WMS»** — один светофор: зелёный, жёлтый («скоро») или красный («сейчас») и что сделать.
- **Копия на флешку** с проверкой каждого файла и напоминанием; **«Вернуться к копии…»** — копия встаёт на место рабочей книги,
  операции после неё WMS доводит по журналу; **зеркало журнала** на другом диске и «Журнал из зеркала»; **контрольная цепочка
  журнала** (ручная правка видна); **проверка дня** при первом запуске; **точки восстановления** перед рискованными действиями;
  «Отложенные операции»; сторож часов и свободного места.
- **Учебное восстановление** раз в месяц: свежая копия открывается отдельно, журнал от неё проверяется до последней операции —
  «восстанавливается» (рабочая книга не меняется).
- **Проверка Calc:** формулы с известным ответом в проверке дня и сразу после обновления LibreOffice.
- Время открытия и сохранения, рост книги и прогноз, «Замер скорости ПК», «Советы LibreOffice», «Лишние ячейки», лёгкий снимок
  для этикеток; карта, сохранённая с книгой, не перестраивается при открытии.

### Помощь и обучение
- «?» на каждом листе, **«Первый день»** (тур с подсветкой кнопок), «Что нового», **«Что делать, если…»**, «Шпаргалка A4»,

## 0.8.0 — PRIME: обновление из рабочей книги, исправления, живой склад

**Версии:** продукт `0.8.0`, ядро `0.8.0-prime`, схема служебных данных `WMS-SYS-5` (новые: `UPGRADE_FROM`, реестр переноса
`_LEG`, фасовка ЕИ `_PACK`), журнал `J1` (без изменений; новая операция `EI_PACK`, у выдач, возвратов, списаний и пересчётов —
поля `PARTS`/`PART_UNIT`/`PART_N` и `PCT`/`PCT_BASE`), контракт снимка `1.1` (без изменений), WMS_TOOLBOX `1.1.3`, книга
обновления `WMS_UPGRADE` `1.0.0`.

Новая версия ставится **из вашей рабочей книги 0.7 со всеми данными** — ничего не вводится заново; старая книга не изменяется
(откат). Всё, что раньше было в отдельных инструментах для каждого дня, — теперь в самой WMS и на живых данных.

### Обновление (D-091)

- **`WMS_UPGRADE.ods`** — четыре кнопки: «ПРОВЕРИТЬ», «РЕПЕТИЦИЯ», «СОБРАТЬ И СВЕРИТЬ», «СДЕЛАТЬ РАБОЧЕЙ» (руководство, раздел 11).
  Рабочая книга находится сама; новая — в новой папке; сверка каждой ячейки старой и новой книги, журнал побайтно, новая WMS
  открывает копию проверки (самопроверка, «остаток = движения», независимая проверка журнала). Любой сбой — копия удаляется,
  отчёт остаётся. Проведённое в старой книге после сборки не теряется: «СДЕЛАТЬ РАБОЧЕЙ» просит собрать заново. Если в старой
  книге поработали уже после перехода — новая WMS предупредит при запуске.
- Отчёт `UPGRADE_SUMMARY.txt` — без данных склада (счётчики, контрольные суммы), его можно прислать разработчику.

### Исправления

- **«Исправить» на «Заказах» спрашивает, что исправить:** этот приход; **позицию заказа** (наименование, артикул, единица,
  категория, поставщик, заказано, № заказа, счёт, дата — во всех строках позиции и в «Наличии»); **коррекцию переноса**
  (получено по старой таблице и остаток на момент переноса, с актом); **снять отмену** заказа или остатка.
- **«Исправить ЕИ переноса»** на «Наличии» — карточка и остаток ЕИ, перенесённого без заказа; «Разобрать» для «Требует разбора».
- **Перенесённый приход** удаляется сторно (если после переноса по нему не было движений), израсходованное до переноса уходит
  вместе с ним.
- **«Сверка переноса»** — каждый перенесённый ЕИ: старое, перенесённое, движения после, «остаток = сумма движений», что проверить.
- **Лист, защищённый чужим паролем,** больше не ломает WMS: операция отказывает до начала («лист … защищён не паролем WMS»),
  запуск называет такой лист; незавершённая операция на таком листе — блокировка с понятной причиной вместо «MARKER_CORRUPT».

### Новое в WMS

- **«Дашборд»** — книга открывается на нём: состояние WMS, плитки дня (ЕИ с остатком, ожидается, пришло, выдано, машины,
  внимание), ожидаемые поставки по сроку, последние операции, чаще всего выдают за 30 дней, без движения 90+ дней, 14 дней
  полосками. Пересчитывается сам после проведения.
- **«Поиск»** — одно поле: номер ЕИ → **карточка ЕИ** с бегущим остатком и проверкой «сходится с «Наличием»»; получатель →
  **«на руках»**; любое слово → все строки рабочих листов с переходом к строке.
- **«Карта склада»** по вашей топологии (лист «Топология», вставить или «Загрузить топологию…»): слои «Занятость», «Выдачи 30
  дней», «Без движения», «Внимание», «Свободные»; щелчок по месту — что на нём лежит; «Не на карте».

- **«Подобрать ЕИ»** на «Выдачах» и «Корректировках»: ЕИ с остатком по части наименования, артикулу или месту, старые первыми.

### Что нового

  ручной отмены. Ожидаемая дата — информация и контроль сроков:
  - на листе «Заказы» ячейка Q подсвечивается, если дата прошла, а позиция ещё ждётся (условное оформление; статус, проведение и

    версий со статусом «Просрочено» читаются как открытые позиции;
  - статусы по дате книги прежней версии при открытии и кнопкой «Обновить статусы» становятся статусами по данным.
- **Статусы старой таблицы пользователя (D-090):** «Ожидаем» — открытый заказ, ждём поставку; «Размещён» — открытый размещённый;
  «Ожидает размещения» — открытый, ещё не размещён (в WMS «Ожидается», в комментарий Z — «Статус до переноса: Ожидает
  размещения»); «Получен без документов» — получено, документов нет; «Отменён» — отменённый заказ. «Отменен» = «Отменён»,

  слова «заказ». Таблица синонимов: «Размещен», «Размещено», «Заказ размещён», «Заказан», «Оформлен», «Ожидается», «В пути», старое
  «Просрочено» — заказ открыт; «Получен», «Оприходовано» — получено; «Частично получен» — частично; «Отменён» — отменено. Рабочий
  статус считает новая WMS по количествам, приходам и документам; старый текст сохраняется дословно (журнал, `LEGACY_ROWS.csv`).
- **Неизвестный старый статус не останавливает перенос:** жёлтое «неизвестный старый статус — состояние рассчитано по данным».
  Останавливает только статус, похожий на отмену, но не из таблицы («Отменить?», «Снят поставщиком»): без его смысла заказ нельзя
  перенести безопасно. Такой статус (и любой другой) можно объяснить один раз в «Настройках» — новая строка **«Свои синонимы
  статусов»** (`Снят поставщиком = Отменено; Едет = Ожидается`), не исправляя строки.
- **Даты:** один разбор для всех дат (N, O, P, Q): `1.9.26`, `01.09.26`, `1.09.2026`, `01.09.2026`, `1/9/26`, `01/09/2026`,
  `1-9-26`, `01-09-2026`, `2026-09-01`, с пробелами, с «г.», со временем, настоящие даты и дата-время Calc; год `26` — 2026.
  Пустая дата остаётся пустой. Непонятная дата — жёлтое замечание, дата пустая, исходный текст — в комментарии Z. Останавливает
  только непонятная дата поступления прихода (без неё WMS не проведёт приход) — или правило «дата поступления = дата документа».
  Специальный приход (Офис, Производство, Детали…) переносится ЕИ без даты — его дата поступления больше не обязательна.
- «2_Проверка»: «С прошедшей ожидаемой датой (заказ ждём, статус не меняется)» вместо «Просроченных», «Неизвестные старые

## 0.6.0 — кандидат в рабочую версию (WMS_PROD_CANDIDATE)

**Версии:** продукт `0.6.0`, ядро `0.6.0-final-core`, схема служебных данных `WMS-SYS-3`, формат журнала `J1`.

### Что умеет WMS

- **Приход по заказу** (лист «Заказы»): заказ → приход → новый ЕИ → «Наличие»; частичные поставки, несколько УПД, исправление, сторно, отмена заказа или остатка.
- **Приход не по заказу** (лист «Иной приход»): Офис, Производство, Детали, Старый склад, Иной.

  - «Иной» — ЕИ «Требует разбора»; «Разобрать» — тип выбирается явно.
- **Выдача** (лист «Выдачи»): ЕИ → количество → получатель → дата; исправление и сторно.
- **Возврат** (лист «Возврат»): к конкретной выдаче, в остаток того же ЕИ.
- **Корректировки** (лист «Корректировки»): перемещение ЕИ на другое место, списание, инвентаризационная корректировка. Исправление и сторно каждой.
- **«Наличие»** — постоянный реестр ЕИ: остаток, место, состояние, источник.
- **Надёжность:**
  - каждая операция записывается во внешний журнал `WMS_Journal/`;
  - после сбоя или выключения — «Восстановить»;
  - Ctrl+Z проведение не отменяет;
  - проведённые строки защищены, копии строк распознаются.
- **Резервные копии** `WMS_Backups/`: ежедневная автоматическая и по кнопке.
- **Инструменты:** «Экспорт для инструментов» (снимок для WMS_TOOLBOX), «Загрузить пакет» (строки от инструментов проводятся обычными проверками).
- **WMS_TOOLBOX** (папка рядом с книгой, для работы WMS не нужна): инвентаризация, аналитика, отчёт руководителю, поиск и история ЕИ, диагностика, этикетки, акты, архив, массовый приход; сверка старых названий, резервная копия на носитель, проверка перед сменой, этикетки TSPL. Инструменты читают только снимок и никогда не открывают рабочую книгу.
- **Перенос старого склада:** `tools/migrate.py` (проверка → перенос в копию → сверка → рабочая книга); ЕИ сохраняют свои номера.
- **Состояние и проверки:**
  - «Состояние системы» — версии, рабочий файл, журнал, копии, размер;
  - «Проверка перед работой» — LibreOffice, макросы, запись журнала и копий, автосохранение, размер книги, защиты листов;
  - «Самопроверка» — полная сверка служебных данных.

### Совместимость

- **Книги этапов 1–5** (схемы `WMS-SYS-1`, `WMS-SYS-2`) ядро 0.6.0 не открывает: запуск блокируется с понятной причиной. Данные переносятся импортёром в новую книгу.
- **LibreOffice:**
  - проверенные версии (24.2, 26.2) — без замечаний;
  - другая версия 7.x и новее — предупреждение: до работы с настоящими данными выполните пакет проверки ПК;
  - версия старше 7 — ошибка «Проверки перед работой».
- **Формат книги** — только ODS.

### Ограничения

- Разделения ЕИ (split) и пересчёта единиц нет; перемещение — только ЕИ целиком.
- Скорость открытия и сохранения на складском ПК ещё не измерена (облачные замеры — в отчётах этапов); складской ПК и принтер проверяются пакетом `docs/PC_VALIDATION.md`.
- Нет принудительной записи журнала на диск (fsync).
