**Главная ценность прототипов — найденные дефекты.** Каждый из них в production дал бы молчаливое расхождение или ложную блокировку. Все исправлены в прототипе и превращены в обязательные правила (раздел 9.2):

1. **Служебная «копия до изменения» (before-image) хранилась с управляющими символами.** ODS их не сохраняет. После сохранения посреди операции запуск падал с ошибкой. Ошибка запуска не блокировала проведение, и в итоге появились дубль №1867, расхождение остатка и повтор seq в журнале. Это P3, прогон 1, 10 FAIL.
2. **Указатель позиции журнала использовался без проверки.** Меняем окончания строк журнала (CRLF ↔ LF) и имитируем аварию. Операция из журнала молча пропадала, а следующая получала тот же № и тот же seq. Это X1b.
3. **Блокировка WMS не снималась, если сеанс был заблокирован по другой причине.** Следующий запуск ложно сообщал «WMS уже открыта». Это P4, прогон на v4.
4. **Счётчик непроведённых строк смотрел только «окно» после последней проведённой строки.** Ошибочная строка выше этого окна была не видна. Это P4.
5. **Заполнение маркером (протягивание) создаёт «проведённые» строки с новыми №.** Они не ловятся правилом «№ повторяется». Лист без защиты — прямая подделка проведённых строк. На защищённом листе — незаметная замена EI и количества во вводимых строках. Это P1, T11.
6. **Ввод количества зависит от языковых настроек ПК.** В en-US «1,500» превращается в 1500, то есть в 1000 раз больше, и проходит порог. Дата в ячейке с числовым форматом превращается в 46143. Это P4 (E2, E2b).
7. **Автозавершение Calc (AutoInput) ломает сокращения получателей.** «пет» + Enter превращается в «петр» и сохраняется как получатель. Это P4 (E5).
8. **Полная проверка ключей при 500k занимает 15 с и +1,3 ГБ памяти.** На ПК с 4 ГБ это риск падения. Порциями — 7 с и +25 МБ. Это P2.

## 1. Среда и общая методика

**Среда:**
- Ubuntu 24.04, облачный контейнер: 4 vCPU (Intel Xeon 2,8 ГГц), 15 ГБ RAM, без swap.
- LibreOffice 24.2.7.2 — Calc из пакетов Ubuntu 24.04. Это совпадает с классом рабочей машины из раздела 2: Ubuntu + LibreOffice. Конкретный ПК склада недоступен.
- LibreOffice 26.2.5.2 из официальных noble-backports. Распакован в папку сессии без установки в систему, использован для перекрёстной проверки версий (X3).
- Интерфейс: виртуальный экран Xvfb. Использованы настоящие команды интерфейса (`.uno:Copy/Paste/Cut/InsertRows/DeleteRows/Undo/SortDescending/FillSeries/CloseDoc…`), настоящие нажатия клавиш через службу UITest (окна автофильтра, диалог «Документ используется», AutoInput, AutoCorrect) и события листов/документа. Часть проверок выполнена без интерфейса (headless) — в таблицах это отмечено.
- **Важно про цифры P2.** Во время работы контейнер был перезапущен на другом физическом хосте. Одна и та же книга 500k открывалась за 20,6 с на первой машине (ВМ-1) и за 42–46 с на второй (ВМ-2). Код ядра v1 и v6 на одной машине работает одинаково (раздел 3.4). Поэтому абсолютные цифры скорости зависят от железа в 2–2,5 раза.

**Прототип (одноразовый, не production).**

Книга с точной структурой листов:
- `Заказы` — 28 колонок A–AB, `Выдачи` — 18 колонок A–R (раздел 3). Новых колонок нет.
- Новые листы `Возврат` и `Наличие`. `Наличие` — реестр EI с плотной адресацией: номер строки = номер EI.
- Скрытые служебные `_SYS` (счётчики, маркер операции, указатель журнала, зарегистрированный путь) и `_DET` (индекс деталей по артикулу).

Ядро на LibreOffice Basic:
- `WmsCore` — 2 494 строки: проведение, журнал, восстановление, блокировки, копии.
- `WmsUI` — лёгкие обработчики D-008.
- `WmsBench` — замеры.

Рядом с книгой — `WMS_Journal/` и `WMS_Backups/` (D-002, D-003).

**Данные — синтетические, с заданным числом движений.**
- Движение = строка `Заказы`, `Выдачи` или `Возврат`.
- ≈40 % приходов, ≈58 % выдач, ≈2 % возвратов.
- Профили поступления: обычный поставщик, Детали, Офис, Производство, Старый склад.

**Независимый оракул (Python).** Пересчитывает остатки по проведённым строкам и сверяет с реестром. Проверяет:
- уникальность № / EI / DET-номеров / № возвратов;
- отсутствие отрицательных остатков;
- состояние маркера;
- непрерывность seq в журнале;
- что каждая выдача из журнала есть в книге ровно один раз.

Оракул запускается после каждой группы проверок.

**Версии ядра прототипа.** Тесты находили дефекты, ядро исправлялось:
- v2 — позиция чтения журнала;
- v3 — детектор «книга сохранена без макросов»;
- v4 — безопасный формат before-image и «запуск при ошибке блокирует проведение»;
- v5 — снятие блокировки по владельцу и подсчёт непроведённых строк по всему листу;
- v6 — проверка позиции журнала по содержимому.

Итоговые P1, P3, P4 перепрогнаны на v6. P2 полностью выполнен на v1 и выборочно повторён на v6 (10k/100k/500k).

## 2. P1 — идентичность строки без новых колонок, защита, действия пользователя

### 2.1 Среда
LibreOffice 24.2. Книги 3 000 и 100 000 движений. Интерфейсные команды через диспетчер, автофильтр — через настоящее окно фильтра (GUI, Xvfb), заполнение — через `.uno:FillSeries`.

### 2.2 Методика
Модель связи (из `CLAUDE_REPORT.md`, раздел 8, по D-001):
- **Ключи строк.** Выдачи — A «№», его присваивает только WMS. Заказы — V (EI), для деталей — DET-номер. Возврат — № возврата.
- **Номер строки — только подсказка.** Он проверяется. При несовпадении строка ищется одной формулой MATCH (C++).
- **Защита.** Проведённые учётные ячейки заблокированы. Лист защищён с разрешёнными «вставкой строк» и «автофильтром». Структура книги защищена. Колонки ввода и информационные колонки открыты.
- **Копии.** Изменение нескольких ячеек (вставка) проверяется: строка с чужим ключом помечается «КОПИЯ строки №…», не проводится и снимается кнопкой «Очистить копию».
- **Отмена.** На время записи операции стек отмены блокируется и после неё очищается.

После каждого действия запускается оракул.

### 2.4 Вердикт
**PASS WITH CONDITIONS.** По критерию «ни одного двойного проведения, ни одного молчаливого расхождения» все проверенные действия либо заблокированы, либо найдены системой. Условие — защита листа включена всегда, а правила 2.6 реализованы в ядре.

### 2.5 Найденные проблемы и поведение LibreOffice
- **Макрос пишет в защищённые ячейки без снятия защиты.** Защита листа защищает от пользователя, но не от ошибки в коде. Нужен единый слой записи.
- **Вставленная строка наследует блокировку соседней.** Строка, вставленная над проведённой, закрыта для ввода. Ввод остаётся в строках внизу.
- **Состояние блокировки вставленных при копировании ячеек непостоянно** (в разных прогонах — по-разному). На защиту от копий опираться нельзя, нужен признак КОПИЯ.
- **Заполнение увеличивает числа и хвостовые цифры в тексте** (№, «ЕИ-00000007», количество, дата) — T11.
- **Диапазон автофильтра не расширяется на новые строки сам.**
- **Опция защиты «вставка строк»** в прототипе выставлена правкой XML. В рабочей книге её ставят один раз в диалоге «Защитить лист». После сохранения, перезапуска и перехода между версиями LibreOffice она сохраняется (T10, P4-3, X3).

### 2.6 Обязательные изменения архитектуры (P1)
1. **Ключи строк по схеме 2.2.** Номер строки — подсказка с проверкой. Поиск — одной C++-формулой, не циклом Basic.
2. **Правило копии расширить.** Строка с ключом, появившаяся не через WMS (вставка, заполнение, перетаскивание), — КОПИЯ, если ключ повторяется в листе **или** этот ключ WMS никогда не выдавала (№ ≥ NEXT_NO). Второе правило в прототипе не реализовано — пробел найден тестом T11.
3. **Обработка изменения нескольких ячеек (до ~200 строк)** обновляет предпросмотр каждой строки: EI → наименование/остаток. Иначе заполнение незаметно меняет EI и количество.
4. **Отмена блокируется на время операции и очищается после.** Побочный эффект, о котором надо сказать пользователю: после каждого проведения история отмены его ручного ввода пропадает.
5. **Защита всегда включена, пароль защиты пользователь в работе не использует.** Сортировка и удаление строк в учётных листах недоступны — только фильтр (D-001).
6. **Ядро поддерживает диапазон автофильтра:** расширяет его при проведении или задаёт до конца листа.

### 2.7 Что не удалось проверить
- Перетаскивание мышью (drag-and-drop) и маркер заполнения мышью. Проверены эквивалентные команды (Вырезать/Копировать/Вставить, «Заполнить ряд»). Настоящее перетаскивание — 5 минут ручной проверки на рабочем ПК.
- «Найти и заменить → Заменить все» по листу с проведёнными строками. Специальная вставка с опциями (транспонирование, «пропускать пустые», операции).
- Сочетания клавиш и поведение интерфейса в Windows-версии LibreOffice.

### 2.8 Блокирует ли Release 1
Нет, при выполнении 2.6.

## 3. P2 — производительность

### 3.1 Среда
- **Серия 1:** ВМ-1, LibreOffice 24.2 с интерфейсом (Xvfb), ядро v1, 10k / 50k / 100k / 250k / 500k движений.
- **Серия 2:** ВМ-2, ядро v6, 10k / 100k / 500k.

### 3.2 Методика
Для каждого размера:
- Строится книга и открывается в интерфейсе.
- Выполняются 200 выдач по одной (выделение строки + обработка событий интерфейса), затем 500 выдач пакетом («Провести все»), 100 приходов, 50 приходов деталей, 100 возвратов.
- Три лёгких обработчика D-008 вызываются через ввод в ячейку: EI → данные, артикул детали → наименование + EI, сокращение → ФИО.
- Защита снимается и ставится ×2.
- Поиск EI сравнивается четырьмя способами: прямая адресация, UNO EnumerableMap, MATCH, findFirst.
- Фильтр через API и через окно, лёгкое условное форматирование.
- Измеряются память процесса (RSS), время сохранения и повторного открытия.
- В конце — оракул и сторож, который отмечает любые всплывшие окна.

Больших Basic `Collection` нет (по заданию).

### 3.5 Вердикт
**PASS WITH CONDITIONS.**
- **Целевой отклик ≤ 0,5 с (раздел 46) выполнен с запасом на обеих машинах.** На 500k p95 выдачи — 23–39 мс, прихода — 70–176 мс, возврата — 81–88 мс. Худший отдельный случай — 381 мс.
- **Открытие и сохранение растут линейно с размером книги.** На 250k: открытие 11 с и сохранение ≈ 20 с (ВМ-1; на ВМ-2 250k не замерялся, по соотношению ожидаемо ≈ 25 с открытия). На 500k: открытие 21–46 с, сохранение ≈ 43–45 с, память до 1,1 ГБ.
- **Масштаб по разделу 46:** ≈ 2 000 приходов + 3 000 выдач в месяц ≈ 60 000 движений в год. 100k — примерно 1,7 года истории, 250k — примерно 4 года, 500k — примерно 8 лет в рабочей книге.

### 3.6 Найденные проблемы
- **Индексы в памяти при запуске недопустимы.** EnumerableMap на весь реестр — 3,6 с на каждый запуск при 500k. Прямая адресация (строка `Наличие` = номер EI) — 0,08 мс и без построения.
- **`findFirst` в 7–8 раз медленнее MATCH** на больших листах.
- **Сохранение после каждой операции невозможно.** 8–45 с на 100k–500k — это подтверждает D-002 (журнал вместо сохранения).
- **Полная проверка одним массивом при 500k — +1,3 ГБ памяти.** На ПК с 4 ГБ это риск падения. Проверка запускается при каждом старте, пока книга не сохранена через WMS, и может превратиться в цикл падений.
- **Память растёт за сеанс:** на 500k — с 685 до 1 096 МБ после ≈ 1 050 операций, фильтров и условного форматирования. Причина не исследована: кэш или утечка.
- **Автосохранение LibreOffice на большой книге будет «замораживать» интерфейс** на время сохранения: 8 с на 100k, 45 с на 500k. Отдельно не замерялось, следует из времени сохранения.

### 3.7 Обязательные изменения архитектуры (P2)
1. **Реестр EI — плотная адресация** (строка = номер EI). Никаких полных индексов в памяти при запуске. Индекс деталей — маленький, строится при первом обращении.
2. **Поиск и агрегаты по большим листам — одноразовой C++-формулой** в служебной ячейке (MATCH / COUNTIF / SUMIFS / SUMPRODUCT). Не `findFirst` и не цикл Basic.
3. **Полные проверки в Basic — только порциями по нужным колонкам** (например, 3 колонки × 20k строк).
4. **Книга не сохраняется после операций** (D-002). Сохранение — действием пользователя; интервал автосохранения LibreOffice подбирается под время сохранения книги.
5. **Порог размера рабочей книги.** Ориентир — ≤ 250k движений. Точное значение — по замеру на рабочем ПК. Архивирование (раздел 38) может оставаться «следующим слоем» (раздел 57), только если стартовый объём после миграции плюс прирост за 2–3 года меньше ~200k.
6. **Повторить P2 на рабочем Ubuntu-ПК с копией реальной книги до миграции.** Раздел 46 требует показать результат честно до миграции. Разброс ×2 между двумя облачными машинами показывает, что только этот замер достоверен.

### 3.8 Что не удалось проверить
Рабочий ПК (процессор, диск, объём памяти). Реальная книга (её формулы, стили, форматирование, фактический объём). Длинный рабочий день (многочасовой сеанс). Пауза автосохранения. Сетевой диск.

### 3.9 Блокирует ли Release 1
Нет. Обязательный шаг до миграции — 3.7.6.

## 4. P3 — сбои и восстановление

### 4.1 Среда
LibreOffice 24.2, с интерфейсом и без. Принудительное завершение `kill -9`, аварийное падение LibreOffice (SIGSEGV), внедрение искусственных ошибок в шаги 1–6 каждой операции.

### 4.2 Методика
Протокол операции (D-002 и `CLAUDE_REPORT.md`, раздел 9):
1. Проверки без записи.
2. Маркер STARTED с before-image, то есть старыми значениями всех ячеек, которые будут изменены.
3. Записи.
4. **Строка в журнале — точка фиксации.**
5. COMMITTED и LAST_SEQ.

Ошибка до шага 4 — откат по before-image. После шага 4 — только доведение до конца.

При запуске:
- STARTED → откат по маркеру.
- Журнал сравнивается с книгой. Если в журнале есть операции, которых нет в книге, проведение блокируется до явного действия «Восстановить» (довести) или «Отложить хвост журнала».

### 4.4 Вердикт
**PASS WITH CONDITIONS.** На v6 каждая операция существует ровно один раз или явно помечена. Дублей и отрицательных остатков нет ни в одном сценарии. Условия — правила 4.6, без которых прогон 1 показал реальные повреждения.

### 4.5 Найденные проблемы
- Два дефекта — before-image и позиция журнала — давали молчаливое повреждение. Исправлены.
- **Встроенное восстановление LibreOffice не защищает несохранённые операции** (C2c). Защищает только журнал.
- **Остаточный риск — отключение питания.** Basic не умеет принудительно сбрасывать файл на диск (fsync). ОС сбрасывает запись в течение секунд. Последние операции могут пропасть и из журнала, и из книги — согласованно, но выданный товар останется неучтённым.
- **Журнал, копии и книга лежат на одном диске.**

### 4.6 Обязательные изменения архитектуры (P3)
1. **Протокол 4.2 — единственный путь записи.** «Проведено» пользователь видит только после записи в журнал. Одна функция «применить операцию» используется для ввода, доведения из журнала, сторно и исправления.
2. **Служебные данные в ячейках — только печатные символы.** Разделители экранируются, проверка — «сохранить → открыть → прочитать».
3. **Запуск «fail-closed».** Любая ошибка или несогласованность при запуске блокирует проведение с понятным сообщением. Выход — только явными действиями: «Восстановить», «Отложить хвост журнала», «Снять блокировку WMS», «Сделать рабочим файлом».
4. **Строка журнала:** `J1;seq;время;экземпляр;тип;поля…;END;длина`, UTF-8, LF. Файл на месяц, только дозапись. Перед каждой дозаписью — проверка владения: размер файла равен ожидаемому, иначе стоп и блок (проверено E4). Seq строго непрерывен, разрыв — остановка восстановления.
5. **Позиция журнала в книге хранится как `файл|смещение|seq`** и перед использованием проверяется по содержимому: строка, заканчивающаяся на смещении, должна быть записью seq. При несовпадении файл читается целиком.
6. **Доведение из журнала сверяет состояние книги перед применением** и останавливается на первом расхождении.
7. **Блокировка WMS** (файл в `WMS_Journal`) и зарегистрированный путь рабочей книги (проверено C4a, E4).
8. **Рекомендация (не блокирует):** ИБП для складского ПК. Периодическая копия `WMS_Backups` и `WMS_Journal` на другой носитель.

### 4.7 Что не удалось проверить
Настоящее отключение питания и сбой ОС. Антивирус, который блокирует файл журнала. Журнал на сетевом диске или в синхронизируемой папке.

### 4.8 Блокирует ли Release 1
Нет, при выполнении 4.6.

- **E2b — ввод количества с настоящими нажатиями клавиш.** Сравнивались обычные ячейки и ячейки текстового формата «@», в профилях ru-RU и en-US:

| Ввод | ru-RU, обычная | en-US, обычная | Текстовая ячейка (обе локали) → строгий разбор |
|---|---|---|---|
| `1,5` | 1,5 | текст (ошибка) | 1,5 |
| `1.5` | текст (ошибка) | 1,5 | 1,5 |
| `0,5` | 0,5 | текст (ошибка) | 0,5 |
| `1,500` | 1,5 | **1500 (молча!)** | 1,5 |
| `2,250` | 2,25 | **2250 (молча!)** | 2,25 |
| `01.05.2026` | дата | текст | отклонено |
| `1.5.26` | дата | текст | отклонено |
| `12.03` | текст | 12,03 | 12,03 |
| `1 000` | 1000 | текст | отклонено |
| `1e3` | 1000 | 1000 | отклонено |
| `-1` | −1 | −1 | отклонено |
| `1/2` | «½» (AutoCorrect) | «½» | отклонено |

AutoInput не дополняет строки, начинающиеся с цифры: «1» + Enter при «1,5» и «1,500» выше в колонке осталось «1».

- **E5 — AutoInput и сокращения получателей (D-008, раздел 18), настоящие нажатия клавиш.** В колонке уже есть «Петров П.П.» и «Петренко А.А.»:
  - при включённом AutoInput (по умолчанию) «пет» + Enter → **«петр»**: общий префикс, обработчик его не знает, строка осталась с получателем «петр»;
  - «ива» + Enter → «Иванов И.И.» — случайно верно;
  - «Ка» + Enter → «Кабель» (проверено в колонке количества E2b; AutoInput работает так в любой колонке с текстом);
  - после отключения AutoInput через конфигурацию (действует сразу) или командой `.uno:AutoComplete`: «пет» → «Петров П.П.», как задумано.
- **X3 — перекрёстная проверка версий LibreOffice 24.2 → 26.2 → 24.2: PASS.**
  - В 26.2 книга 24.2 открылась: запуск «согласованы». Выдача, приход и возврат введены через интерфейсные команды и проведены. Автоподстановка работает, Ctrl+Z безвреден, правка проведённой ячейки заблокирована. Защита 4 листов и структуры цела, кнопка на листе «Главная» сохранила привязку к макросу, блокировка WMS снята при закрытии.
  - 26.2 сохранил файл в формате **ODF 1.4** (был 1.3). Флаги «вставка строк», Basic и привязки событий сохранились.
  - Обратно в 24.2: запуск «согласованы (seq 6)», проведение OK, вставка строк разрешена, seq журнала непрерывны, оракул чист.
  - Ограничение теста: в 26.2 сеанс выполнялся внутри книги (Basic через интерфейсные команды, без экрана), см. 5.6.

### 5.4 Вердикт
**PASS WITH CONDITIONS.** Состояние, индексы, защита, события, связи, журнал и копии переживают перезапуск и смену версии LibreOffice. Условия — 5.5.

### 5.5 Обязательные изменения архитектуры (P4)
1. **Ввод количества не должен зависеть от языковых настроек ПК.**
   - Рекомендуемый вариант: колонки ввода количества в текстовом формате + строгий разбор. Принимать «1,5» и «1.5», не более 3 знаков после разделителя. Даты, «1e3», «1 000», «-1», «1,5,0» — ошибка. После проведения в ячейку записывается число.
   - Разбор проверен в обеих локалях. Подключение к проведению в прототипе не сделано: нужна запись числа и включение этой ячейки в before-image.
   - Минимальный вариант: при запуске проверять десятичный разделитель LibreOffice; если он не «,», проведение блокируется.
   - Порог MAX_QTY остаётся второй линией.
2. **AutoInput Calc выключается при запуске WMS** и восстанавливается при закрытии. Это глобальная настройка и затрагивает другие открытые книги — сказать пользователю.
3. **Получатель вне справочника — предупреждение при проведении**, а не ошибка: свободный текст разрешён разделом 18.
4. **Перенос или восстановление рабочей книги — только через явное «Сделать рабочим файлом».** Копии и резервные копии, открытые напрямую, не проводят.
5. **Блокировка WMS снимается по владельцу, не по состоянию сеанса.** «Снять блокировку WMS» — явное действие после аварии.
6. **Отключённые макросы обнаруживаются** по метке сохранения при следующем запуске. После этого — полная проверка порциями (3.7.3).
7. **Настройки LibreOffice на рабочем ПК:** папка WMS — доверенное расположение для макросов (уровень безопасности не ниже «Высокий»), интервал автосохранения. Ошибка компиляции любого модуля Basic отключает все макросы книги — это ловит тот же детектор.

### 5.6 Что не удалось проверить
- **ПК разработчика на Windows ↔ рабочий Ubuntu** (раздел 2: рабочая машина — Ubuntu, разработка частично на Windows). Windows-машины нет. Частично заменено:
  - профилем en-US (X1, E2b);
  - журналом с окончаниями CRLF (X1, X1b);
  - перекрёстной проверкой более новой версии LibreOffice, которая сохраняет ODF 1.4 (X3).
  Не проверены файловые блокировки Windows, антивирус, пути с `\`, шрифты и интерфейс Windows-версии.
- **LibreOffice 26.2 в режиме с интерфейсом.** Только без экрана: драйвер тестов на Python не может передавать объекты листов между 24.2 и распакованной 26.2, поэтому сеанс 26.2 выполнялся встроенным в книгу Basic через интерфейсные команды. Для самой WMS это не важно — она целиком на Basic.
- **Конкретная версия LibreOffice и настройки безопасности макросов** на рабочем ПК склада.
- **Печать, панели инструментов документа** (кнопка на листе «Главная» проверена).

### 5.7 Блокирует ли Release 1
Нет для начала разработки. Пункт 5.5.1 и проверка «ПК разработчика ↔ рабочий Ubuntu» на реальных машинах — обязательны до пилота (раздел 55, «Кроссплатформенные»).

## 7. Подводные камни LibreOffice / Basic (для разработчика ядра)

1. **Запись макросом (API) игнорирует защиту листа.**
2. **ODS не сохраняет управляющие символы в тексте ячеек.**
3. **Выполнение `Error n` после того, как вызванная функция сама обработала ошибку, может быть проигнорировано.** Для отката используйте явный `GoTo`.
4. **`TextInputStream.readLine` оставляет `\n`/`\r`** в последней строке и в файлах с CRLF — обрезать.
5. **В `SimpleFileAccess` 24.2 нет `openFileAppend`.** Нужно `openFileReadWrite` + `seek(getLength())`.
6. **Снимать блокировку WMS нужно по событию `OnPrepareUnload`** (оно срабатывает при закрытии окна пользователем); `OnUnload` для этого поздно. Закрытие через API это событие не вызывает.
7. **Число из ячейки может прийти разными типами VarType** (2–7) — принимать все числовые.
8. **`Private Const` одного модуля не виден из другого.**
9. **Зарезервированные слова как имена (`base`, `empty`) ломают компиляцию всей библиотеки.** Одна ошибка компиляции отключает ВСЕ макросы книги. Нужна проверка компиляции перед выпуском.
10. **VBA-функции (`InStrRev` и др.) без `Option VBASupport 1` недоступны.**
11. **Заполнение увеличивает хвостовые цифры в тексте** («ЕИ-00000007» → «ЕИ-00000008») и числа.
12. **AutoCorrect заменяет «1/2» на «½».** AutoInput дополняет текст по колонке до общего префикса.
13. **Распознавание чисел зависит от локали приложения** (en-US: «1,500» = 1500). Дата в ячейке с числовым форматом становится обычным числом.
14. **Диапазон автофильтра не растёт сам.**
15. **Без блокировки отмены одно Ctrl+Z откатывает часть записей макроса.**
16. **Копия `.bak` и автовосстановление LibreOffice не сохраняют несохранённые изменения после падения.**
17. **LibreOffice 26.2 сохраняет ODF 1.4.** 24.2 открыл такой файл без потерь (X3).
18. **Тестовая инфраструктура (на WMS не влияет):**
    - первый запуск нового профиля завершается кодом 81 («перезапуск»), запускать нужно через `soffice`/`oosplash`, а не `soffice.bin`;
    - без экрана LibreOffice не выполняет макросы документа, открытого из командной строки;
    - для форм в Calc нужен пакет `libreoffice-base-core` (он всегда ставится вместе с `libreoffice-calc`).

## 9. Ответы на три вопроса

### 9.1 Можно ли начинать разработку ядра?

**Да.** Архитектура A (Calc + Basic + журнал) прошла все четыре риск-проверки. Архитектурных блокеров нет, а все найденные дефекты исправлены в прототипе.

Условия:
1. **Сначала внести в MASTER SPEC обязательные изменения 9.2.** Они задают контракты ядра: протокол проведения, журнал, запуск, ключи, копии, ввод.
2. **Начинать ядро со «скелета надёжности».** Одна функция «применить операцию», журнал, маркер, запуск и восстановление, блокировки. Затем выдача → приход → возврат. Протокол прототипа можно брать как проверенный образец, но ядро пишется заново по спецификации.
3. **Параллельно с разработкой, но до миграции и пилота — два замера на реальной технике:**
   - P2 на рабочем Ubuntu-ПК с копией реальной книги (3.7.6);
   - перенос файла «ПК разработчика ↔ рабочий Ubuntu» с проверкой ввода количества (5.5.1, 5.6).

### 9.2 Какие изменения MASTER SPEC обязательны?

**A. Проведение, журнал, запуск** (разделы 26–28, D-002):
1. **Двухфазный протокол с before-image и точкой фиксации «строка журнала».** До неё — откат, после — только доведение. «Проведено» — после журнала. Одна функция «применить операцию» для ввода, доведения, сторно и исправления.
2. **Формат журнала:** `J1;seq;время;экземпляр;тип;поля;END;длина`, UTF-8, LF. Файл на месяц, только дозапись, проверка владения перед каждой дозаписью. Seq непрерывен, разрыв — стоп.
3. **Позиция журнала в книге `файл|смещение|seq`** с проверкой по содержимому. При несовпадении — полное чтение.
4. **Запуск «fail-closed»** и явные действия пользователя: «Восстановить», «Отложить хвост журнала», «Снять блокировку WMS», «Сделать рабочим файлом».
5. **Служебные данные в ячейках — только печатные символы.**
6. **Блокировка WMS** (файл в `WMS_Journal`, снимается по владельцу) и зарегистрированный путь рабочей книги.
7. **Отмена блокируется на время операции и очищается после.**

**B. Идентичность строк и защита** (разделы 3, 29, D-001):

8. **Ключи строк:** `Выдачи`.A — только WMS; `Заказы`.V / DET-номер; `Возврат`.A. Номер строки — подсказка с проверкой, поиск — одной формулой.
9. **Правило копии: ключ повторяется ИЛИ WMS его не выдавала.** Пометка «КОПИЯ», «Очистить копию». Полная проверка порциями после сеанса без макросов (метка сохранения).
10. **Защита:** проведённые учётные ячейки заблокированы; «вставка строк» и «автофильтр» разрешены; сортировка и удаление строк недоступны; пароль защиты не для повседневной работы; диапазон автофильтра поддерживает ядро.
11. **Непроведённые строки считаются по всему листу одной формулой.** «Провести все» работает по окну, строки вне окна показываются в отчёте запуска.

**C. Ввод** (разделы 17, 18, 22, D-008):

12. **Количество — ввод, не зависящий от локали** (текстовые ячейки + строгий разбор, после проведения — число; как минимум блок при не-русском десятичном разделителе). Порог MAX_QTY — вторая линия.
13. **AutoInput выключается на время работы WMS.** Получатель вне справочника — предупреждение.
14. **Изменение нескольких ячеек (вставка, заполнение)** — обновление предпросмотра каждой строки.

**D. Объём и скорость** (разделы 29, 38, 46, 47):

15. **Реестр EI — плотная адресация** (строка `Наличие` = номер EI). Никаких полных индексов в памяти при запуске.
16. **Поиск и агрегаты — одноразовые C++-формулы.** Полные проверки в Basic — только порциями по нужным колонкам.
17. **Порог размера рабочей книги (ориентир ≤ 250k движений)** и замер на рабочем ПК до миграции. Архивирование обязательно при приближении к порогу.
18. **Требования к настройкам LibreOffice на рабочем ПК:** доверенное расположение для макросов, интервал автосохранения, AutoInput под управлением WMS.

### 9.3 Что безопасно отложить?

- **Архивирование (раздел 38)** — если стартовый объём после миграции плюс прирост за 2–3 года < ~200k движений. Иначе не откладывать (P2).
- **Индексы в памяти / EnumerableMap для всего реестра** — не нужны вообще (P2). Раздел 29 можно упростить: для EI достаточно плотной адресации, для деталей — маленький ленивый индекс, кнопка «Перестроить индексы» — только для него.
- **Многопользовательский режим и сетевой диск** — вне Release 1 (один кладовщик, раздел 2).
- **Ускорение окна фильтра по колонке EI** (3–4 с на 500k) и тяжёлое условное форматирование.
- **Просмотрщик журнала, отчёты по журналу, архив журналов старше N месяцев.**
- **Интеграция с аварийным восстановлением LibreOffice** — не нужна: её заменяет журнал (C2c).
- **Перенос старых возвратов из `Выдачи.M/N`** (D-004).
- **Оформление панели инструментов** — кнопки на листе «Главная» работают и переживают смену версии (X3).
- **Автоматическая «починка» копий и дублей** — достаточно ручной кнопки «Очистить копию».

**Не откладывать:**
- ввод количества без зависимости от локали;
- отключение AutoInput;
- правило копии «ключ не выдавался WMS»;
- полные проверки порциями;
- замер на рабочем ПК;
- проверку переноса «ПК разработчика ↔ рабочий Ubuntu».
