## До P1–P4 (D-001…D-010)

Источник: задание на прототипы P1–P4.

### D-001. Проведённые строки защищаются.

После `Провести` блокируются все поля, влияющие на складской учёт: ЕИ, количество, получатель, единица, место и другие учётные значения.

Разрешаются фильтры. Ручная правка проведённых учётных ячеек запрещена.

Исправление выполняется только через `Исправить`, удаление — только через `Удалить`.

Система должна быть устойчива к вставке строк, фильтрам и другим изменениям расположения строк. Связь строится по ключу, а не по физическому номеру строки.

При проведении блокируется Undo, чтобы `Ctrl+Z` не мог отменить только часть операции.

### D-002. Внешний журнал операций обязателен.

Рядом с основной WMS разрешены служебные папки:

`WMS_Journal/`

`WMS_Backups/`

После успешного проведения каждой операции в append-only журнал записываются её номер, тип, время, ЕИ, входные данные и остаток до/после.

Пользователь получает статус `Проведено` только после успешной записи операции в журнал.

Если LibreOffice упал или книга была закрыта без сохранения, при следующем запуске WMS сравнивает журнал с последней сохранённой операцией книги и предлагает восстановить недостающие движения.

Основную ODS-книгу после каждой выдачи сохранять нельзя: при больших объёмах это стало бы главным источником задержек. Ориентировочные тесты Claude показали сохранение около 9 секунд на 100k движений.

### D-003. Резервные копии разрешены и обязательны.

Базовая политика:

* автоматическая копия при первом рабочем запуске дня;
* обязательная копия перед обновлением;
* обязательная копия перед миграцией;
* автоматическая ротация старых копий;
* возможность ручной кнопки `Создать резервную копию`.

Журнал защищает текущие несохранённые операции, backup защищает сам файл WMS.

### D-004. `Выдачи.M Вернул` и `Выдачи.N Вернул в %` становятся legacy/информационными.

Все новые возвраты проводятся только через отдельный лист `Возврат`.

Система не пытается искусственно распределять новый возврат по старым строкам `Выдачи` и не заполняет M/N автоматически.

Источник истины для новых возвратов:

`Возврат + складская операция возврата`.

Старые значения M/N при миграции сохраняются.

### D-005. Канонический код товара

`Заказы.V` и `Выдачи.L` являются ЕИ.

Канонический формат:

`ЕИ-00000001`

Система должна распознавать ввод:

`123`

`00000123`

`ЕИ-00000123`

`EI-00000123`

и приводить его к одному каноническому значению.

### D-006. Частичные приходы

Первое фактическое поступление может использовать исходную строку заказа.

Следующие УПД той же позиции создают новые строки.

`Заказанное количество` у дополнительных строк не повторяется.

Связь дополнительного поступления с исходной позицией заказа хранится в служебной структуре.

### D-007. Наличие

`Наличие` становится пользовательским представлением постоянного реестра ЕИ.

Вторую независимую таблицу с теми же остатками создавать запрещено.

### D-008. Лёгкие обработчики разрешены

Запрещены не все обработчики изменений, а тяжёлые обработчики.

Разрешён лёгкий обработчик для:

* ЕИ → данные товара;
* артикул детали → название + ЕИ;
* сокращение → полное имя.

Он должен мгновенно завершаться при изменении нерелевантной ячейки и ничего не сканировать.

### D-009. GitHub

Исходники Basic хранятся текстом, а не только внутри бинарного ODS.

GitHub является долговременной памятью проекта.

Claude запрещено самостоятельно делать commit, push, PR, создавать/переключать ветки или менять `main`, если конкретное задание пользователя этого явно не разрешает.

### D-010. Следующий этап

Бизнес-интервью основного ядра завершено.

До написания production-WMS выполняются четыре технических риск-прототипа:

P1 — идентичность строк и защита.

P2 — производительность.

P3 — crash recovery и внешний журнал.

P4 — сохранение/повторное открытие и Windows ↔ Ubuntu.

Только после их результатов принимается решение о начале реализации ядра.

## D-011…D-024 (утверждены ранее, восстановлены 25.09.2026)

Источник: канонический текст пользователя из задания Core Phase 2. Эти решения не новые: они были утверждены ранее и потерялись при переносе документов.

### D-011 — История получателя

История показывает, что и когда выдавалось получателю и какие возвраты были зарегистрированы. Она не утверждает, что невозвращённый товар физически до сих пор находится у этого человека.

### D-012 — Получатели

Люди, `Офис`, `Производство` и другие допустимые текстовые получатели являются значениями одного типа для истории выдач. Поддерживается справочник сокращений. Одно сокращение принадлежит одному получателю и должно быть уникальным.

### D-013 — Проведённые строки

После проведения учётные ячейки защищаются. Ручная правка полей, влияющих на учёт, запрещена. Изменения выполняются через штатные команды WMS.

### D-014 — Ctrl+Z

Учётная операция защищается от частичного отката через Undo. Исправления и удаление проводятся только командами WMS.

### D-015 — Внешний журнал

Разрешён и обязателен append-only журнал рядом с WMS для восстановления проведённых, но ещё не сохранённых в ODS операций.

### D-016 — Резервные копии

Разрешена отдельная папка backups. Базовая политика — одна копия рабочего дня плюс обязательные копии перед обновлением и миграцией.

### D-017 — Подстановки

Разрешены лёгкие обработчики изменения нужных ячеек, если они не сканируют большие диапазоны, защищены от повторного входа и отключаются в Safe Mode.

### D-018 — Архив

Архивируется тяжёлая история, но все ЕИ навсегда остаются в постоянном реестре. Архивный ЕИ может снова стать активным после возврата.

### D-019 — Отдельные инструменты

Тяжёлые функции выполняются отдельными ODS-инструментами через read-only снимок основной WMS.

### D-020 — Ежедневный отчёт

Нужен один ежедневный отчёт руководителю. WMS формирует черновик автоматически, после чего пользователь может вручную изменить итоговый текст.

### D-021 — Аналитика

`WMS_ANALYTICS.ods` анализирует текущую историю и архивы, строит статистику, прогноз дефицита, рекомендации заказа и нагрузку. Тяжёлая аналитика не выполняется автоматически в рабочей WMS.

### D-022 — GitHub

GitHub является долговременной памятью проекта. Исходники Basic хранятся текстом. Commit/push/PR/ветки выполняются только в явно разрешённом объёме.

### D-023 — Риск-прототипы

До основной разработки обязательны P1–P4: идентичность строк, производительность, crash recovery, persist/reopen/cross-platform.

### D-024 — Завершение интервью

Основное бизнес-интервью завершено. Незначительные правила уточняются перед соответствующим модулем и не должны бесконечно задерживать разработку.

## 25.09.2026 — после P1–P4

### D-025 — P1–P4 приняты
Все четыре риск-прототипа имеют PASS WITH CONDITIONS и не блокируют Release 1.

### D-026 — Начинать ядро можно
Сначала обязательные правила отчёта P1–P4 включаются в MASTER SPEC. Затем ядро начинается со скелета надёжности, а не с пользовательских функций.

### D-027 — Journal commit point
Точкой фиксации операции является успешная append-запись во внешний журнал. До неё — rollback, после неё — recovery/доведение.

### D-028 — Fail-closed
Любая ошибка запуска, несогласованность журнала, блокировка или повреждение служебных данных запрещает проведение до явного решения пользователя.

### D-029 — Journal format
Журнал: UTF-8, LF, monthly append-only, непрерывный seq, проверка владения и позиции по содержимому.

### D-030 — Quantity parser
Количество вводится независимо от локали LibreOffice через строгий парсер. Разрешены `1,5` и `1.5`; неоднозначные форматы блокируются.

### D-031 — AutoInput
Calc AutoInput отключается на время работы WMS, чтобы не ломать сокращения и свободный ввод.

### D-032 — Copies
Ключ, который WMS не выдавала, является копией/подделанной строкой даже если он уникален. Такая строка не проводится.

### D-033 — Dense EI registry
`Наличие` использует плотную адресацию по номеру ЕИ. Полный in-memory индекс ЕИ не строится.

### D-034 — Full checks
Полные проверки идут порциями только по нужным колонкам.

### D-035 — Book size
Ориентир рабочего файла ≤250k движений. Точный лимит определяется на реальном складском ПК.

### D-036 — Real hardware gate
До миграции обязательны P2 на рабочем Ubuntu с реальной копией и тест переноса developer PC ↔ warehouse Ubuntu.

### D-037 — Prototype code
Одноразовый прототип не является production-кодом. Проверенные идеи переносятся в чистое ядро, а не копируются без ревью.

### D-038 — GitHub authorization
Даже после P1–P4 commit/push/PR/ветки запрещены без конкретного разрешения пользователя.

## 25.09.2026 — Core Phase 2 «Выдачи» (утверждено при приёмке этапа)

Источник: сообщение пользователя о приёмке Core Phase 2. Предложения — `CLAUDE_REPORT_CORE_PHASE2_ISSUES.md`, разделы 10 и 11.

### D-039 — Удаление выдачи
Удаление выдачи = статус `Удалено (сторно)`. Строка остаётся с № и данными, заблокирована, № не переиспользуется.

### D-040 — Исправление выдачи
Исправление выдачи = одна составная операция `ISSUE_FIX`.

### D-041 — Сохранение при активном фильтре
При сохранении с активным фильтром WMS временно снимает скрытие строк, не удаляя условия фильтра, сохраняет книгу и затем восстанавливает фильтр.

### D-042 — Защита непроведённой строки
Для непроведённой строки защищены A, C, D, G, J, K, P, Q, R.

### D-043 — Колонка F «Количество в %»
Пока правила процентной выдачи не утверждены, заполненная F `Количество в %` блокирует проведение.

### D-044 — Журнал при запуске и самопроверка
- обычный startup использует подтверждённую сохранённую позицию и читает только необходимый хвост;
- если позиция не подтверждена, сначала читается соответствующий месячный файл;
- полный исторический журнал читается только как fallback;
- полный self-check всего журнала является отдельной диагностической операцией, а не частью обычного запуска.

## 25.09.2026 — Core Phase 3 «Приход и заказы» (утверждено при приёмке этапа)

Источник: сообщение пользователя о приёмке Core Phase 3. Предложения — `CLAUDE_REPORT_CORE_PHASE3_RECEIPTS.md`, раздел 14. Пункты 1, 2, 4, 6–12 и 14 утверждены в предложенной редакции, пункты 3, 5, 13 и 15 — в редакции пользователя. Номер решения = 44 + номер пункта раздела 14.

### D-045 — Документ прихода
Документ считается внесённым, когда заполнены и C (номер), и O (дата). Иначе приход — «без документов»: позиция, полученная полностью, получает «Получено без документов», а Y показывает, чего не хватает.

### D-046 — Документ позднее
Добавить документ позднее — через «Исправить» (C, O, G закрыты после проведения). Это одна операция журнала; ЕИ тот же, нового прихода нет.

### D-047 — Просрочка частично полученной позиции
*Заменено D-089 (28.09.2026): статуса «просрочено» больше нет.*

Если:
- 0 < получено < заказано;
- остаток не отменён;
- Q заполнена;
- Q < текущей даты,

статус — `Частично получено / просрочено`. Таким образом:
- 0 получено + срок прошёл → `Просрочено`;
- частично получено + срок не прошёл → `Частично получено`;
- частично получено + срок прошёл → `Частично получено / просрочено`;
- остаток отменён → `Частично получено / остаток отменён`, просрочка больше не применяется;
- получено полностью → `Получено` или `Получено без документов`.

Y исходной строки по-прежнему показывает, сколько осталось получить.

### D-048 — Обязательные поля прихода
A № заказа, B наименование, H заказанное > 0, I единица, F факт > 0, N дата поступления, U место. Приход без строки заказа с H (товар без заказа) обычным приходом не проводится — это «Иной приход» следующих этапов или новая строка заказа.

### D-049 — Дата поступления N
N остаётся обязательной. Для первого прихода из исходной строки дата не подставляется молча: если N пустая, проведение блокируется. В окне «Ещё поступление» поле N предварительно заполнено сегодняшней датой как удобное предложение; пользователь может изменить дату перед подтверждением. То же правило — для будущих диалоговых сценариев прихода, где это уместно: дата по умолчанию = сегодня, но не скрытая автоматическая фиксация.

### D-050 — Отменённая позиция
Полностью отменённая позиция («Отменено») окончательна: приход по ней не проводится, «вернуть» её нельзя — новая строка заказа. Отменить заказ можно, пока по позиции нет действующих приходов (в том числе после сторно всех приходов).

### D-051 — Поступление при отменённом остатке
Поступление по позиции с отменённым остатком разрешено («Ещё поступление»): товар физически пришёл; статус пересчитывается («Получено», если получено ≥ заказано).

### D-052 — Копирование в дополнительную строку
В дополнительную строку копируются A, D и B, E, I, L, M, P, R, S, T, J из исходной строки; H, K, Q, Z, AA не копируются (Q — ожидание позиции, живёт в исходной строке).

### D-053 — Состояние ЕИ прихода в «Наличие»
«Активен» для прихода, «Приход удалён (сторно)» после сторно; источник — «Заказ <№ заказа>».

### D-054 — Антидубль
Ключ: поставщик + номер документа + артикул (или название) + факт F + дата документа O (или дата поступления N), с нормализацией написания. Только предупреждение; сторнированные приходы не учитываются.

### D-055 — Цена и сумма
Цена J: число ≥ 0 (0 допустим), до 3 знаков после запятой, после проведения закрыта и исправляется через «Исправить». K «Сумма» — информационное поле пользователя.

### D-056 — Требование к будущей миграции
Все старые ЕИ — в плотном реестре «Наличие» и записи `_RCV`/`_ORD` для перенесённых строк «Заказов» с ЕИ; NEXT_EI выше любого кода книги. Иначе перенесённые строки будут считаться копиями, а новые номера — конфликтовать со старыми.

### D-057 — Книга Phase 2 не обновляется
Отдельный инструмент обновления книги Phase 2 сейчас не делается. Реальный пилот Phase 2 не используется как источник учёта, который необходимо сохранить. Ручная проверка и будущий пилот начинаются с новой актуальной книги Phase 3. Будущая миграция реальных старых ЕИ, остатков и истории — отдельный этап.

### D-058 — «Отложить хвост журнала» и счётчики
«Отложить хвост журнала» поднимает NEXT_EI и NEXT_NO выше номеров отложенных операций: номер, который уже мог попасть на наклейку или в документ, повторно не выдаётся.

### D-059 — Проведение блока строк
Каждая видимая строка с F проводится отдельной атомарной операцией:
- строка без F пропускается;
- обычная ошибка валидации одной строки не останавливает остальные строки блока;
- результат показывает, сколько строк проведено, сколько пропущено и сколько отклонено с ошибкой;
- любая системная ошибка WMS — ошибка журнала, recovery, блокировка/fail-closed, ошибка `ApplyOperation`, повреждение состояния или невозможность гарантировать атомарность — немедленно прекращает дальнейшую обработку всего блока.

Пакет после системной ошибки не продолжается.

## 26.09.2026 — Core Phase 4 «Возвраты» (утверждено при приёмке этапа)

Источник: сообщение пользователя о приёмке Core Phase 4. Предложения — `CLAUDE_REPORT_CORE_PHASE4_RETURNS.md`, раздел 15. Пункты 1–9 и 11 утверждены в реализованном варианте, пункт 10 — в редакции пользователя (более строгая зависимость истории). Номер решения = 59 + номер пункта раздела 15.

### D-060 — Номер возврата
Отдельный счётчик `NEXT_RET` в `_SYS` (ключ зарезервирован схемой `WMS-SYS-1` с этапа 1; схема не меняется): № возвратов 1, 2, 3… независимо от № выдач; монотонный, не переиспользуется. «Отложить хвост журнала» поднимает `NEXT_RET` выше № отложенных возвратов (как NEXT_EI и NEXT_NO, D-058).

### D-061 — Кто возвращает
Обычный возврат — только от получателя исходной выдачи: «От кого возвращено» (I) = получатель выдачи, подставляется автоматически. Другой получатель — отказ; передача товара между получателями — отдельный будущий сценарий. Историческое правило v0.1 §20 («вернуть может и другой человек», «возврат не обязан связываться с конкретной строкой выдачи») не действует: возврат всегда привязан к конкретной проведённой выдаче по её №.

### D-062 — Дата возврата
Дата возврата (H) обязательна; в строке не подставляется. Окно «Найти выдачу» предлагает сегодняшнюю дату, пользователь может её изменить (как D-049 для прихода). Дата возврата не раньше даты выдачи.

### D-063 — Исправление выдачи с действующими возвратами
При действующих возвратах `ISSUE_FIX` меняет только количество: не ниже возвращённого; больше — при достаточном остатке. ЕИ, получатель и дата выдачи меняются только после сторно этих возвратов.

### D-064 — Сторно возврата и место
Сторно возврата место ЕИ не возвращает: место — текущее место ЕИ; сторно меняет только количество.

### D-065 — Место при возврате
Другое место в J перемещает ЕИ в той же операции возврата (отдельного перемещения нет); «Контроль» заранее показывает «место ЕИ изменится: «…» → «…»».

### D-066 — Исправление возврата
«Исправить» (`RETURN_FIX`) меняет количество, дату и место возврата; выдача и ЕИ те же. Другая выдача — сторно и новый возврат.

### D-067 — Список «Найти выдачу»
Окно показывает не больше 100 последних выдач ЕИ, которые ещё можно вернуть; более старую выдачу вводят по № в B.

### D-068 — Книга Phase 3 не обновляется
Ядро этапа 4 книгу этапа 3 не открывает (нет листов «Возврат», `_RET`, `_ISS`; запуск блокируется с понятной причиной). Ручная проверка и пилот возвратов — с новой книги этапа 4; перенос данных — этап миграции (D-056, D-057).

### D-069 — Сторно прихода и зависимые движения
Если по ЕИ существуют действующие выдачи, `RECEIPT_DEL` запрещён — независимо от того, полностью ли они возвращены. Для сторно прихода пользователь:
1. сторнирует действующие возвраты этого ЕИ;
2. сторнирует связанные выдачи;
3. только после отсутствия действующих зависимых движений выполняет сторно прихода.

Причина: после `RECEIPT_DEL` не должно оставаться действующей исторической цепочки «выдача → возврат», ссылающейся на сторнированный исходный приход. Исторические строки сторнированных операций остаются, номера не переиспользуются. Отказ — понятным сообщением: «По этому ЕИ есть связанные выдачи/возвраты… Сначала выполните сторно зависимых операций». Проверка — без полного прохода по листам: одна формула движка Calc (COUNTIFS) по занятым строкам «Выдач» (ЕИ + статус «Проведено» / «Проведено (исправлено)») и служебной таблицы `_RET` (ЕИ + LIVE).

Уточнение пользователя к D-069 (26.09.2026, до финального commit этапа 4). Для `Удалить приход` порядок должен быть:

1. сначала проверить, разрешено ли `RECEIPT_DEL`;
2. если есть связанные действующие выдачи/возвраты — сразу показать отказ и НЕ открывать окно подтверждения;
3. только если сторно допустимо — показать подтверждение `Удалить приход?`;
4. после подтверждения выполнить операцию.

Логику D-069 не менять.

Возврат — в единице выдачи. Если единица ЕИ в реестре другая — отказ; пересчёт единиц — отдельный этап.

оставшихся частей, и последняя часть закрывает остаток ровно в 0 (3 бут: 0,333 + 0,334 + 0,333). Точность частей — 0,01 при
меньше 10 частях в единице, 0,1 — до 100, целые — до 1000 (больше 1000 — отказ: «профиль — в метрах, не в миллиметрах»).
Возврат частями всей выдачи закрывает её точно. **Проценты** (v0.1 §21, снимает D-043): «Количество в %» (F) или «25%» в E —
процент от того, сколько пришло по ЕИ (приход «Заказов», строки «Иного прихода», остаток переноса); нет прихода в книге — отказ.
Только выдача и списание; E и F вместе — отказ. В «Контроле» до проведения — «К выдаче: 1 кан = 0,25 шт». Журнал строки хранит,
как задано количество: `PARTS`, `PART_UNIT`, `PART_N` или `PCT`, `PCT_BASE`; `QTY` — всегда в единице документа.

### D-100 — Одна позиция — несколько мест
Место ЕИ может быть списком: `1-2-3, 1-2-4` (`;`, `+`). Каждое место списка — как пишут (D-095); на карте ЕИ на каждом месте
(занятость, выдачи 30 дней, без движения, внимание), поиск находит по любому, «Перемещение» принимает список, «Куда положить?»
при уже указанном месте спрашивает «добавить или заменить». `5,12,3` без пробелов — одно место (как раньше).

### D-101 — Скорость того, что уже есть: две библиотеки и экран без перерисовки во время записи (1.0)
Пользователь: «Главное безопасность и скорость работы того что уже есть»; +28 % к проведению в 0.8 — «изменение большое все
таки». Две причины, обе устранены:
- каждое имя в библиотеке Basic замедляет поиск остальных имён той же библиотеки — модули страниц и дополнений (WmsLegacy,
  WmsPrimeUi, WmsView, WmsPack, WmsDash, WmsFind, WmsMap и все новые 1.0) живут в библиотеке `WmsPlus`, ядро `Standard` — набор
  модулей 0.7.2; `WmsInit` загружает `WmsPlus` (книга без неё работает); кнопки и события привязаны к библиотеке своего модуля;
- Calc перерисовывает видимый лист после каждой ячейки, записанной в любом месте книги: при открытом листе с цветными правилами
  («Заказы», «Дашборд», «Поиск») — до 1 мс на ячейку, в 10 раз дороже самой записи. Во время операции (`ApplyOperation`)
  экран не перерисовывается (`lockControllers` внутри скобки Undo; снимается в `UndoEnd` на любом пути, в том числе при
  откате и сбое; блокировку, оставшуюся от прерванного макроса, снимает следующая операция), после — одна перерисовка.
  Формулы пересчитываются как прежде; события «содержимое изменено» на записи макросов не срабатывают ни с блокировкой, ни
  без (проверено). Отметку «книга изменена» Calc под блокировкой откладывает до её снятия — поэтому блокировка не ставится
  вокруг кода, который снимает эту отметку (запуск, страницы, «Обновить статусы»).
Замер 200 выдач на одной книге: 0.7.2 — 95–101 мс, 0.8 — 114–118 мс, 1.0 — 87 мс на выдачу.

### D-102 — Надёжность 1.0: журнал, копии, сохранённый файл (1.0)
- **Отметка последней записи журнала.** Позиция журнала в книге хранит и отметку своей последней записи (время и длина строки:
  `файл|смещение|seq|отметка`). Запись журнала с тем же № и другой отметкой — книга и журнал от двух разошедшихся копий WMS:
  запуск блокируется (`JOURNAL_OTHER_COPY`), «Восстановить» их не смешивает. Позиция без отметки (книги до 1.0) читается как прежде.
- **Журнал отстал от книги** (последние строки не дошли до диска — питание пропало сразу после сохранения: книгу LibreOffice
  при сохранении сбрасывает на диск, а записи журнала из Basic сбросить нельзя — `flush()` потока файла этого не делает, проверено
  `strace`) или журнал от другой копии: «Сделать рабочим файлом» переносит прежний журнал в `WMS_Journal/старый_журнал_<дата_время>`
  (копия со сверкой размера, затем удаление; ничего не теряется), начинает новый журнал записью `START` с текущего состояния книги
  и сразу сохраняет книгу. Книга — главный источник; восстановление из более старых копий «по журналу» после этого возможно только
  до этого момента (об этом говорит окно).
- **Резервные копии.** Неполная копия (размер не равен книге) удаляется, старые копии не трогаются. Часы компьютера позади последней
  копии — предупреждение. Только что сделанная копия ротацией не удаляется (при отставших часах она сортировалась бы первой).
  Ежедневная копия «за сегодня» — только целая копия этой книги.
- **Сохранённый файл говорит правду без макросов.** На время сохранения на «Главной» и «Дашборде» — «WMS не запущена — макросы
  выключены» и как включить (доверенные источники); после сохранения — живая панель. Calc записывает эти записи в стек отмены даже
  под блокировкой, а отмена записи, сделанной во время сохранения, роняла LibreOffice: после сохранения стек отмены очищается, как
  WMS делает после каждой операции. Строка состояния «Дашборда» — незащищённая ячейка (во время сохранения защита не меняется).
- **Старая книга после перехода заперта:** мастер обновления кладёт в её `WMS_Journal` блокировку WMS с текстом «ЭТА КНИГА БОЛЬШЕ
  НЕ РАБОЧАЯ: WMS перенесена…»; книга и её журнал не меняются, откат — «Снять блокировку WMS» в старой книге.
- **Совпавший пересчёт записывается** (инвентаризация с разницей 0): дата последнего пересчёта ЕИ остаётся в учёте.

### D-103 — Ежедневная работа и вид 1.0 (этапы B и C, выбор пользователя)
- **Несколько выдач разом** (Р1): выделенные строки «Выдач» → «Провести» спрашивает «одним документом / каждую отдельно / не
  проводить»; каждая строка — своя операция `ISSUE` (у всех общий «Документ» B, `ВД-<№>`), ответ на общий вопрос (новый получатель,
  необычная дата) задаётся один раз на блок. Отказ строки не мешает остальным; итоговое окно — только когда что-то не проведено.
- **Окна «Выдать…» и «Принять…»** (Р2, Р6), «Принять всё по заказу» (Р7), «Повторить», «Выдать» из «Наличия» и «Поиска»
  (Р3, Р9), «Вернуть выделенное» из «на руках» (Р8): всё заполняет обычные строки листов и проводит их обычными проверками —
  новых путей записи нет. Количество «всё» (Р12) — весь остаток одной записью (`HOW=ALL`), без хвостов. Горячие клавиши книги
  Ctrl+Shift+P/E/F/W/Q (Р11) хранятся в самом документе.
- **Вид** (В1–В10): шапки колонок ввода светло-жёлтые, колонок WMS серые (и сами ячейки WMS); цвет кнопки — смысл (провести —
  зелёная, отменить/удалить — красноватая, помощник — голубая); подсказка колонки (помощь ввода Calc и заметка шапки); «Главная» —
  меню из трёх групп с красной рамкой «Только если WMS просит» и шестью шагами «Как…»; закреплены колонки «№/ЕИ» и наименование;
  «Почему?» показывает весь «Контроль» строки и что сделать; в «Наличии» нулевой остаток серым и строки через одну; ярлычки листов
  по группам; даты «ДД.ММ.ГГГГ ЧЧ:ММ», без «N мс» в текстах для людей (миллисекунды остаются в результатах для проверок и
  диагностики), значок окна по смыслу (не сделано / проверьте / подсказка). Получатель «Выдач» и «Возврата» — выпадающий список
  «Получателей» (любой текст по-прежнему можно вписать; WMS спросит о новом имени).

### D-104 — Части и металл 1.0 (этап D)
- **«Остаток частями»** (Ч1) — колонка K «Наличия»: формула строки (остаток × частей в 1 единице из `_PACK`), её ставит операция
  `EI_PACK` производной записью; цифры следуют за остатком сами, ядро учёта не пишет лишнего при выдачах.
- **Фасовка по товару** (Ч2): первый приход позиции, у прошлого ЕИ которой (тот же артикул, без артикула — то же наименование, та же
  единица) есть фасовка, — вопрос «задать такую же?». «Ещё поступление» той же позиции переносит фасовку без вопроса (A2).
- **Смена фасовки** (Ч3): остаток в новых частях не целый (для канистр, бутылок, штук) и число выдач по старой фасовке — в окне до
  записи; проведённые выдачи не пересчитываются.
- **Строка выдачи показывает, как выдано** (Ч4): «Проведено · 1 кан», «Проведено · 25 %», «Проведено · весь остаток» — текст
  пишет сама операция (повтор журнала пишет тот же). Начало «Проведено» сохранено — все проверки статуса читают его по началу.
- **Хвосты** (Ч5): «Дашборд» — ЕИ с остатком меньше одной части (без фасовки — меньше 0,01), «Списать хвосты…» — строки
  «Корректировки» «Списание … всё» с одной причиной, проведённые обычными проверками.
- **Фасовка пачкой** (Ч6): ЕИ с остатком без фасовки, наименование которых подсказывает её, — по одному окну «Записать / Пропустить /
  Остановить».
- **Вес метра** (Ч8): документ в кг или т — в окне фасовки «1 м = 2,5 кг»; частей в 1 кг хранится до 6 знаков. В тоннах учёт до
  0,001 т (1 кг) — окно об этом предупреждает (точнее 0,001 — пункт Ч10, не выбран).
- **Слова в количестве** (Ч9): «пол кан», «половина», «четверть», «1/4 кан», «1 1/2 м»; сумма «2 + 1 кан» (одно слово — точно в
  частях; разные единицы — только в пересчёте). Голое «1/2» по-прежнему отказ.
- **Обрезки металла** (Ч7) строятся на операции разделения ЕИ (М1, этап E): обрезок — свой ЕИ с той же карточкой и фасовкой;
  «подобрать обрезок» — ЕИ того же товара с длиной не меньше нужной.

### D-105 — Места и карта 1.0 (этап E)
- **Разделение ЕИ** (М1) — новый вид корректировки «Разделение» (операция `SPLIT`): часть ЕИ становится новым ЕИ (следующий
  номер) с той же карточкой и фасовкой, своим местом и этикеткой; в строке — «Проведено · новый ЕИ-…». Весь остаток не
  разделяется (это перемещение); разделение не исправляется — удаляется (сторно, пока у нового ЕИ нет движений) и проводится
  заново. На нём построены обрезки металла (Ч7).
- **Карта правится на самой карте**: «Править карту» — карта без слоя, место «5.12.3» остаётся текстом; «Сохранить карту»
  сначала показывает проверку (повтор адреса, место без яруса, исчезающие места с ЕИ), прежняя схема — в скрытом листе
  «_TOPO_PREV»; «Отменить правку» возвращает карту по «Топологии». Пока идёт правка, карта сама не перестраивается.
- **Вместимость и слои** (М4, М5): «Места» D — сколько ЕИ помещается; слой «Заполненность»; «Показать на карте» из карточки и
  поиска; двойной щелчок по месту — «Поиск» с этим местом: что лежит сейчас и история места (М6, М12).
- **«Куда положить?» умнее** (М9): учитывает места непроведённых строк, вместимость, не предлагает место дважды и места с тем же
  товаром предлагает первыми.
- **Список мест «+ / −» и диапазон** (М10): в новом месте перемещения «+1-2-5» — добавить место к списку, «−1-2-3» (или «-1-2-3») —
  убрать, остальные места остаются как написаны; в J и в журнал пишется весь новый список. «1-2-3…5» (или «..») — три места:
  так их читают карта, поиск и проверки. В «Исправить» перемещения «+ / −» считается от мест, которые оно записало.
- **Выдача «с места»** (М11): после выдачи с ЕИ на нескольких местах, если что-то осталось, — «Одно из мест опустело?»: Enter —
  «Места не менялись»; выбранное место убирается проведённой строкой «Перемещение» («−место»). При выдаче блоком не спрашивается.
- **Переименовать ряд** (М7): «Ряд 5 → 6» (секция, место) — WMS готовит строки «Перемещение» для всех ЕИ с остатком (не проводит);
  по выбору тут же переименовывает места на карте и в «Места» (прежняя карта — в «_TOPO_PREV»); строки выделены — их проводят
  блоком «Провести». ЕИ без остатка не трогаются.
- **Маршрут сбора** (М8): непроведённые строки «Выдачи» на «Поиске» по порядку мест (ряд, секция, ярус; без места — в конце), с
  количеством, получателем и строкой выдачи; печать — Ctrl+P.

### D-106 — Заказы и поставщики 1.0 (этап F)
- **Возврат поставщику** (З1) — новый вид корректировки «Возврат поставщику» (операции `SUP_RET`, `_FIX`, `_DEL`): остаток
  уменьшается, поставщик, документ и причина — в строке и в журнале; «ждём замену» добавляет новую открытую строку «Заказов».
- **Справочник «Поставщики»** (З8): одно написание, телефон, обычный срок; выпадающий список на «Заказах» (L) и на панели «Прихода
  авто»; «Пополнить из заказов». Лист — свой у снабженца: не защищён и не журналируется (как «Места»).
- **«Снабжение»** (З2, З10): «Ожидаем» — открытые позиции по поставщикам (осталось, ожидаемая дата, опоздание, переход к строке);
  «Нужно заказать» — товары «Номенклатуры» ниже минимума (остаток всех ЕИ товара, в пути, расход за 30 дней, сколько заказать);
  плитка на «Дашборде» (З3 — «осталось получить», «и ещё N», переход двойным щелчком).
- **Заказ** (З4–З7): «Ещё поступление» показывает «заказано · получено · осталось» и предлагает остаток, больше заказанного —
  вопрос; «Отменить весь заказ» одной причиной для всех позиций (причина — в журнале и в «Контроле»); «Повторить заказ» —
  позиция или весь заказ новыми строками; на новой строке — подсказка «эта позиция уже ожидается».
- **Машина и приход** (З9): «Принять товар» на «Приходе авто» открывает позиции этого поставщика.
- **Акт расхождения** (З12) — первый документ страницы «Печать»: поставка одного документа поставщика — по документу и
  фактически, недостача или излишек, брак (возвраты поставщику), подписи сторон; «Сохранить PDF» — файл в «WMS_Документы».

### D-107 — Контроль и учёт 1.0 (этап G)
- **Причина удаления и исправления** (К1) — на всех листах: в журнале `WHY`, в комментарии строки «удалено 19.10.2026 — …»
  (производная запись). Статус «Удалено (сторно)» остаётся точным — его сравнивают проверки и инструменты.
- **«История изменений»** (К2) на «Поиске» — журнал по-русски: дата, время, операция, «было → стало» по ячейкам, причина;
  фильтр по ЕИ, периоду и виду.
- **Документы на бумаге** (страница «Печать», «Печать…» и «Сохранить PDF»): акт списания по выделенным проведённым списаниям —
  позиции частями («1 кан (0,25 шт)»), цена из заказа, сумма, подписи (К3); накладная на выдачу по выделенным выдачам или «всё,
  что выдано <кому> <дата>» с подписями «Выдал / Получил» (К11); её номер — документ выдач или «Н-<№ первой выдачи>» — ставится
  в пустой B выдач одной операцией `ISSUE_DOC` (журнал, восстановление; К12); карточка ЕИ с движениями и всеми исправлениями
  «было → стало» с причиной (К14); инвентаризационная опись места или зоны по порядку мест с пустым «Факт» и сличительная
  ведомость проведённых пересчётов дня — излишки и недостачи с суммами (К4). Суммы пишутся «1 250,50» при любом языке ПК.
- **«Пересчитать место…»** (К5): строки «Инвентаризация» для всех ЕИ с остатком в ряду, секции или месте — учётный остаток,
  сегодняшняя дата, основание, пакет «Пересчёт <зона> <дата>»; ЕИ, уже ждущий пересчёта, второй раз не добавляется; ничего не
  проводится, Ctrl+Z убирает все строки. Совпавший факт проводится с разницей 0 («пересчитано»). Не больше 500 строк за раз.
- **Страница «Отчёты»** — учёт для бухгалтерии и ревизора (модуль `WmsLedger`), отчёты только читают книгу:
  остаток на дату (К7) = остаток сейчас минус всё, что было позже (сторнированное движением не считается — документ исправлен);
  оборотная ведомость по товарам (К8): начало + приход (с излишками пересчёта и разделением) − выдано + возвращено − списано
  (с возвратами поставщику и недостачами) = конец, в единицах и рублях по цене ЕИ (цена — из её прихода; у отделённого ЕИ — цена
  исходного; где цены нет, так и написано); на «Печать» или в CSV; выгрузка движений за период в CSV (К9) — дата, операция,
  документ, ЕИ, приход/расход, цена, сумма, контрагент. CSV — UTF-8 с меткой, «;», запятая в числах (открывается в Excel,
  загружается в 1С). Длинные списки на «Печати» обрезаются с подсказкой «полностью — в файл».
- **Сверка с 1С** (К10): файл остатков из 1С — CSV/TXT (UTF-8 или Windows-1251, «;», табуляция или «,») или первый лист XLSX/XLS/
  ODS (открывается скрыто, только чтение, без макросов); строка заголовков ищется в первых 30 строках («Номенклатура»/«Наименование»,
  «Конечный остаток»/«Остаток»/«Количество», «Артикул», «Ед.»), строки «Итого» пропускаются; сопоставление по наименованию или по
  артикулу; итог — «совпало / расходится / только в 1С / только в WMS». Ничего не проводится.
- **Закрытие месяца** (К13): «Закрыть месяц» сохраняет оборотную ведомость месяца и остатки на его последний день в
  «WMS_Документы» и записывает строку скрытого `_CLOSE` операцией `MONTH_CLOSE` (журнал, восстановление). Закрыть можно только
  прошедший месяц и только позже уже закрытого. Любая операция с датой (`DATE` или `OLD_DATE`) по последний закрытый день —
  выдача, приход, возврат, корректировка, их исправление и сторно — проводится только после окна «Операция задним числом» с
  причиной: в журнале `BACKDATED` (по какое число закрыто) и `BACKWHY`; без причины — не проведено. Проверка стоит в самом
  `ApplyOperation` (один путь записи — одно место), в пачке строк причина спрашивается один раз. Перемещения, фасовка и номер
  накладной закрытый месяц не меняют — не спрашиваются. «Открыть месяц» — с обязательной причиной (`MONTH_OPEN`).

### D-110 — Надёжность 1.0 (этап J)
- **Состояние вне книги**: дата копии на флешку, папка зеркала, докуда проверена цепочка, итог проверки дня, список копий —
  файлы `WMS_State/` рядом с книгой (`wms_state.txt` «ключ=значение», `wms_copies.txt`). Это не учёт: книга от них не меняется,
  потеря папки ничего не ломает.
- **Копия на флешку** (Н1): книга и журнал, каждый файл сверяется по размеру, 8 последних копий; напоминание через 7 дней.
- **«Вернуться к копии»** (Н2): рабочая книга не может заменить свой открытый файл — она пишет приказ (`wms_restore_order.txt`,
  действителен 10 минут), отдаёт блокировку и открывает копию; копия после окончания макроса (асинхронный вызов) закрывает рабочую
  книгу, откладывает её файл («…_отложена.ods»), копирует себя на её место (каждый шаг сверяется по размеру; сбой — рабочая книга
  возвращается) и открывает её; восстановленная книга доводит журнал («Восстановить») и проверяет себя.
- **Зеркало журнала** (Н3): каждая строка пишется и во вторую папку; недоступное зеркало никогда не останавливает проведение;
  «Журнал из зеркала» заменяет испорченные файлы целыми, прежние — в «WMS_Backups».
- **Контрольная цепочка** (Н4): у каждой новой строки журнала `CH=S<16 hex>` — начало SHA-256 (NSS LibreOffice, ≈1,5 мс) байтов
  UTF-8 предыдущей строки. Ручная правка или удаление строки видна проверке дня. Строки до 1.0 — без `CH`, читаются как прежде.
- **Проверка дня** (Н5) при первом запуске дня: остаток = движения, фасовка, ключи листов, цепочка журнала, зеркало.
- **Точки восстановления** (Н6): копия с понятной пометкой перед загрузкой топологии, «Отложить хвост», коррекцией переноса.
- **Отложенные операции** (Н7): что ушло в «Отложить хвост журнала» — списком; выдачу можно вернуть непроведённой строкой.
- **Сторож часов и диска** (Н8, Н9): часы позади журнала — предупреждение; свободно меньше 100 МБ — копия не делается (неполная
  хуже никакой), меньше 1 ГБ — предупреждение.

### D-113 — Качество 1.0 (этап M)

  приход ÷ 100; «весь остаток» не проверяется.
- **«Здоровье WMS»** (Т6) — светофор на «Обслуживании»: красный — сейчас (проверка дня, диск, зеркало, учение не прошло, работа
  остановлена), жёлтый — скоро (копия на флешку, проверка сегодня, учение раз в месяц, ЕИ не на карте), зелёный.
- **Учебное восстановление** (Т7): самая свежая копия открывается отдельно (`WMS_State/drill`, скрыто, только чтение, без
  макросов) и читается; журнал от её операции до последней читается целиком — непрерывен, этой книги, без повреждений. Полный
  повтор журнала на копии — это «Вернуться к копии» (проверено тестом V27), учение его не делает: рабочая книга не меняется.
- **Проверка Calc** (Т8): двенадцать формул с известным ответом тем же движком, которым считают страницы (`SUMPRODUCT`, `MATCH`,
  `INDEX`, `TEXTJOIN`, даты…) — в проверке дня и при запуске после смены версии LibreOffice; расхождение — замечание (проведение от
  формул не зависит).
- **Случайный ввод** (Т11): 1500 случайных строк в разбор количества, частей и места — без внутренней ошибки; случайные выдачи и
  списания не уводят остаток в минус.

  «Арт.: …» только у категории «Детали», «S/N: …», «Выдача по 1 … · в 1 … — N …»), штрихкод всегда последняя полоса. Кратность
  упаковки: фасовка ЕИ главнее, иначе «Номенклатура» R (`GD_PACKQ = 17`; подсказка листа сдвинута в S). Предел — 200 этикеток на
  позицию, 18 позиций на страницу окна; не помещается на «Печать» — отказ до записи на страницу.
- **Акты.** Вид акта подсказывается по получателю (список «офисных» — настройка на «Акты»), выбор за пользователем. Шапка — как в
  образце пользователя, добавлен только номер. Формулировка «акт выдачи» построена по аналогии с актом приёма-передачи (**не
  подтверждена пользователем**).
- **Отчёт дня** — документ Writer по шаблону пользователя из журнала месяца (read-only). Выдачи с датой выдачи раньше дня отчёта —
  «Оцифровка выдач за …». Рабочие дни 5/2 без календаря праздников. Письмо/отправка не делаются: документ локальный.
- **Метизы и категории.** Разбор названия по правилам (тип, размер, DIN/ГОСТ/ISO, класс, покрытие) — без сети и без «ИИ»;
  подсказка категории: слово таблицы = начало слова названия, первая подходящая строка сверху вниз; пользовательская категория не
  заменяется; чужая категория («Инструмент» у «Болтореза») выводит товар из метизов.
- **Обновление 1.0.x → 1.0.2:** `step_102` (листы, список категорий, кнопки, R1/S1 «Номенклатуры»), данные не пишутся; сверка
  каждой ячейки допускает только заголовок R1 и подсказку S1; книга 0.7.x получает те же листы в `step_08`.
- Инженерное: массивы, переданные в процедуры Basic, теряют записи даже с `ByRef` — накопление текстом в `Global`; `IIf` не
  возвращает массив; `WmsOrders.LastRow` учитывает настройки справа (отдельный `AkLastRow`).

### D-117 — Выпуск 1.1.0 (28.10.2026, PRIME 1.1 по выбору пользователя)
- **Без новых операций журнала.** Все новые листы — просмотры (`Наличие по названию`, `Остаток деталей`, `Операции дня`, `ABC-анализ`, `Без движения`, `Метизы`, `Проверка названий`,
  `Без категории`) или справочники кладовщика (`Стандарты`, `Синонимы`, `Календарь`, `Настройки`, `Категории`): не защищены, в журнал не пишутся, восстановление по журналу их не касается.
  Обновление (`step_110`) данных не пишет; `compare_books` допускает только заголовки/подсказки, перечисленные в `allowed_change`, а производные листы исключены из сверки ячеек.
- **Защита реестра «Наличие» (`WmsGuard`).** «Строка N — ЕИ-N» проверяется одной формулой движка Calc (`SUMPRODUCT`) при каждом открытии и сохранении; нарушено → блокировка `REGISTRY_ORDER`
  и слова «что делать». `SaveGuard` (OnSave): прежний файл на диске сохраняется копией `good` («последняя без ошибок»), если он ещё не скопирован (`GOODSIZE` — размер файла,
  которому уже сделана своя копия, в файле состояния вне книги); `SaveDoneGuard` (OnSaveDone): зелёное сохранение → копия `good` не чаще раза в 20 минут. Сортировка реестра не
  «чинится» автоматически: пользователь решает (закрыть без сохранения / вернуться к копии), журнал доводит проведённое.
- **«Восстановить» довозит пополнение «Иного прихода»** (`SP_REFILL` с `EI_TYPED`); мастер принимает книгу с хвостом журнала (пробное довезение на копии при сборке, довезение при «Сделать рабочей»).
- **«Иной приход» по номеру ЕИ** — только для типа «Детали» и ЕИ-частей: независимый оракул и самопроверка требуют `SP_REFILL` лишь для них; в журнал пишется артикул карточки, `ART_KEY`, поле `EI_TYPED`.
- **Умный поиск.** Индекс строится блоками (`WmsNames.Fold` + `Spaced`), пересобирается инкрементально (строки с неизменным текстом берут прежний свёрнутый текст); запрос раскладывается на группы
  (слова с основами и синонимами; токены: стандарты с эквивалентами из «Стандарты», размеры «м8 30» → «м8х30»); сортировка подсчётом; нечёткий «Возможно, вы искали» — Левенштейн по словам реестра; прочие
  листы ищутся по регулярным выражениям со «Латиница/Кириллица»-классами. Измерено: 1,5 тыс. ЕИ — индекс ≈0,5 с, запрос 80–260 мс; 20 тыс. ЕИ — индекс ≈7,7 с, запрос 1–4 с (реальный масштаб ≈1,3 тыс.).
- **Большие операции** (`WmsAsk.BigAsk`): порог — лист «Настройки» (`BIG_QTY`, 1000, 0 — не спрашивать), два подтверждения подряд. **Номер акта** — следующий по максимуму реестра и журнала (`AkNextNo`).
- **Справочники из копии** (`WmsDirs`): копия открывается скрыто, только на чтение, без макросов; значения отличающихся справочников подставляются **только по согласию**; журнал, реестр и журналируемые листы не трогаются.
- **Календарь и периоды** (`WmsPeriod`, `WmsDocs.PeriodReport`): график 5/2 + исключения листа «Календарь» (праздники 2026–2027 внесены по правилу переноса и помечены «проверьте»); отчёт за период — отчёты дней подряд (≤62 дней).
- **Локальность** (`WmsLocal`): книга читает собственные тексты макросов (библиотеки Standard и WmsPlus), связи, формулы с функциями, читающими интернет; слова поиска собраны из частей (модуль не принимает себя за находку);
  места запуска программ компьютера (`Shell`, открытие файла, ярлык, файловая система Windows) считаются и сверяются с замыслом (3/2/1/1) — новое место показывается. Гиперссылки в тексте ячеек изнутри книги
  не перечислить — это делает `tools/offline_audit.py` по файлу. Настройки самой LibreOffice (проверка обновлений, отчёт об аварии) только читаются и показываются.
- **«Проверить этот ПК»**: принтер ищется среди установленных по имени (`XP-420B` в любой записи), показывается принтер по умолчанию; «Пробная этикетка» только собирает страницу «Печать» — печать остаётся действием пользователя.
- **Документ к приходу** (`WmsAttach`): файл копируется (размер сверяется) в `WMS_Документы/<Заказ №|Документ №>/`, имена не затираются; в книгу и журнал ничего не пишется; открытие папки — программой компьютера.
- **Горячие клавиши**: Ctrl+Shift + буква, `HOTKEYS_10` + `HOTKEYS_11` хранятся в документе (`hotkeys_10` вызывается и при обновлении); привязка по коду клавиши (положению), поэтому русская раскладка не мешает
  (**проверено только как привязка; нажатие на реальной клавиатуре с русской раскладкой не проверялось**).
- **LibreOffice.** Наборы прогнаны на 24.2.7 и 26.2.5 (backports Ubuntu); версия пользователя 25.8.7.3 в среде проверки недоступна (загрузки The Document Foundation закрыты) — `TESTED_LO` остаётся `24.2|26.2`, на 25.8 «Проверка перед работой»
  честно пишет «не проверялась». Расхождение версий: `moveByName` вперёд ставит лист перед местом назначения в 24.2 и после него в 26.2 (сборка проверяет и повторяет перенос назад).
- Инженерное (LibreOffice Basic): нет `ChrW`, `Round`, `InStrRev`, `StrReverse`; зарезервированы `lib`, `base`, `list`, `std`, `oR`; переменная, названная как функция, её затеняет; `Collection` хранит строки и числа, но не массивы
  (массив возвращается первым элементом); `ReDim Preserve` в цикле теряет поздние записи; `On Error GoTo` в цикле срабатывает один раз; `Err` остаётся установленной (не проверять `Err = 0`), а вызов другой процедуры в обработчике ошибки
  стирает `Error$` — текст ошибки сохранять до него.

### D-118 — Выпуск 1.1.1 (29.10.2026, серийные детали одним действием)
- **Без новых операций журнала.** `WmsSerial.ReceiveSerial` — драйвер над прежним: ставит в строку количество (число номеров) и категорию «Детали» (если пусто), проводит строку теми же `SpecialPostRow` / `ReceiptPostRow`,
  затем `WmsParts.SerialSplit(ЕИ, номера)` (цепочка `SPLIT` + `EI_PROP`). Если проведение отказало, изменённые клетки ввода возвращаются, номера остаются в окне (`gSzText`). Если приход проведён, а разделение остановилось —
  «PARTIAL»: ЕИ назван, остальное делается кнопкой «Серийные…» (части разделения уже в журнале, как и в прежнем пути).
- **Один ЕИ на артикул «Детали»** (индекс `_ART`, `ArtLookup` отказывает при повторе ключа) — инвариант не менялся: новая партия принимается в ЕИ артикула. Отделить весь остаток нельзя (`WmsAdjust`: «отделить весь остаток нельзя»), поэтому
  последняя деталь партии остаётся в ЕИ со своим номером; если ЕИ был пуст и нёс номер выданной детали, `PropSet` заменяет номер — прежний пишется в примечание ЕИ («ранее № …», до 200 знаков) отдельной операцией `EI_PROP`
  (журнал хранит и `OLD_SERIAL`). Лист «Серийные детали» разбирает эти пометки и показывает номер как «заменён в ЕИ».
- **Лист «Серийные детали»** — просмотр без записи: свойства `_PROP` (номер, примечание), реестр, последняя проведённая выдача ЕИ (`Выдачи`, статус «Проведено…»); пересборка при открытии, если журнал сдвинулся, и при вводе в «Найти» / «Показывать выданные».
- **Этикетка:** «Арт.:» — для категории «Детали» или любого ЕИ с серийным номером.
- **Обезличенная копия** очищает листы-просмотры 1.1 (в 1.1.0 они оставались со своими данными; найдено при разборе).
- **Обновление 1.1.0 → 1.1.1:** `CORES_SAME_SCHEMA` включает 1.1.0, `step_111` (лист, кнопки, горячие клавиши), сверка допускает новый лист.
- **Скорость (инженерное):** `Public Const` — цена каждого вызова макроса (≈33 мкс за константу библиотеки, измерено: 1500 лишних — +50 мс на вызов), `Private Const`, процедуры, комментарии и `Global` почти бесплатны
  (1500 `Global` — +5 мс). `tools/private_consts.py` переводит в `Private` константы, которых не упоминает ни другой модуль, ни инструмент, ни тест. Имена процедур в библиотеке уникальны (тест V60).

### D-119 — Выпуск 1.2.0 (29.10.2026, сборка деталей и справочник инструмента ЧПУ по просьбе пользователя)
- **Сборка детали — одна операция `ASM_BUILD`.** Не «новый тип учёта», а составная корректировка: позиции уходят со своих ЕИ строками `_ADJ` вида `KIT` (как у комплектов), деталь приходит ещё одной строкой в её **постоянный ЕИ**
  (индекс артикулов `_ART`, как у «Иного прихода» типа «Деталь»: один артикул — один ЕИ; первая сборка заводит ЕИ и запись в индексе, остальные пополняют). Записи сборки несут `AJ_BOOK` (остаток детали до: пусто у сборки,
  заведшей ЕИ) и `AJ_FACT` (после) — по ним сборка отличается от сборки комплекта (`AsmIsBuild`), сверка остатка (`WmsAdjust.AdjustCheck`, оракулы) знает её. Источник строки детали — «Сборка: корректировки № a–b»,
  как «Перенос»: аудит «ЕИ без прихода» их не считает ошибкой. Отмена — `ASM_DEL` (стор­но всей группы записей); невозможна, если у ЕИ детали был иной остаток после сборки, а сборка, заведшая ЕИ, — если по нему были
  выдачи, возвраты, корректировки, приходы.
- **Описание детали — справочник пользователя** (лист «Сборка деталей», без защиты, не в журнале, как «Комплекты»): «Собрать деталь из ЕИ…» записывает его по **артикулам** позиций, а не по номерам ЕИ (ЕИ меняются, артикулы нет);
  позиция по названию без артикула допускается. Деталь не может входить сама в себя; два артикула у одной детали, нечисловое или неположительное количество — отказ до записи.
- **Серийные номера сборки** — тем же `WmsSerial.SerialApply`, что и при приходе: номера у **целых** штучных деталей; ЕИ детали с фасовкой номеров не принимает.
- **«Инструмент ЧПУ» — просмотр без записи**, как «Метизы»: список строится из «Наличия» (`WmsCat.StockGroups`), разбор названия — **свои правила** (`WmsTool.TlRecord`), не нейросеть и не интернет: типы и виды, размер (Ø10×50, «10х50», диапазон «4-20»),
  Z, материал, покрытие, стандарт, обозначение (ER/BT/SK/HSK/МК, код пластины, SDS). Принцип — **«что не нашлось, остаётся пустым»** (как решение 1.1 для метизов): число без метки читается размером только там, где у типа есть диаметр.
  Таблица из 110 реальных названий проверена вручную и закреплена тестом (V68). Стандарты инструмента **не засеяны** в «Стандарты» (нет надёжного источника в проекте) — пользователь вписывает сам.
- **Привязка к категориям не обязательна:** позиция берётся по типу из названия (кроме тех, чья категория — метизы), а по категории с «ЧПУ» или «режущий» — любая (тип «Прочее»); у «Категорий» новых книг есть строка «Инструмент ЧПУ»
  (в обновляемой книге справочник «Категории» **не меняется**).
- **Инженерное.** (1) В LibreOffice Basic `And`, `Or`, `Xor`, `Eqv`, `Imp`, `Mod` — **один уровень старшинства**, слева направо: `A Or B And C` = `(A Or B) And C`. Проверка `precedence_traps` в `basic_compile_check.py`
  требует скобок во всех смешанных выражениях. (2) Скорость листа инструмента — разбор названия кэшируется в памяти (`TlRecordC`, без аналогов стандарта: они читаются из «Стандартов» заново), названия без слова типа
  и без кода пластины отбрасываются сразу.

### Инженерные заметки 0.8 (не решения пользователя)
- Скорость страниц: перебор строк в Basic стоит 30–300 мкс на строку (вызов функции ≈ 15 мкс; **имя другого модуля — константа
  `WmsConfig` или `Global` — 15–25 мкс при каждом обращении в цикле**: в горячих циклах константы копируются в локальные
  переменные). Поэтому «Дашборд» и «Карта склада» считают листы формулами движка Calc в ячейке `_IDX` (`WmsOrders.ScratchEval`):
  `SUMPRODUCT`, `TEXTJOIN` номеров строк, `FREQUENCY` по дням; место каждого ЕИ — двоичный поиск `LOOKUP` в отсортированной
  самим Calc таблице мест на скрытых колонках карты (`MP_KEY_COL`). Внутри `IF` по целым колонкам ветви — только ссылки и
  арифметика: `IF(…; LOOKUP(…); …)` или `IF(…; VALUE(…); …)` вычисляется поэлементно (47 с и 10 с на 40 000 строк вместо
  0,3 с). `MATCH` с массивом искомых без сортировки — тоже поэлементно (47 с). Базовый ряд `FREQUENCY` не может быть пустым
  (ошибка) — строки вне диапазона получают 99. Результат `TEXTJOIN` в 480 000 знаков читается.
- «Лежит без движения 90+ дней» без перебора всех движений: ЕИ с остатком минус ЕИ, у которых есть движение за 90 дней
  (`TEXTJOIN` ЕИ свежих строк по каждому листу); дни — последним движением только для показанных десяти.
- Имена в Basic не различают регистр: `K As String` и `k As Long` в одной процедуре — ошибка компиляции модуля.
- LibreOffice Basic: `Base` и `Name` — ключевые слова (имя переменной ломает модуль целиком), `Like` — оператор: переменная `like`
  роняет сам LibreOffice при компиляции библиотеки (1.0, проверка компиляции теперь вызывает обе библиотеки и падает на второй); `Private` у процедур не скрывает их от
  других модулей (одноимённая процедура модуля, стоящего раньше, перехватывает вызов) — имена новых процедур уникальны в
  библиотеке; `And`/`Or` вычисляют обе части — индексы проверяются вложенными `If`; после `On Error Resume Next` ошибки дальше
  в процедуре могли пропускаться — словари на `Collection` читаются через `CollGet`/`CollPut` со своим обработчиком.
- Кнопки, привязанные «к ячейке», в LibreOffice 24.2 приводили к бесконечной записи временного файла при сохранении — кнопки
  остаются привязанными к странице, а «Главная» устроена так, что растущие строки ниже кнопок.
- Карта: цвет — условное форматирование по скрытой сетке кодов справа от карты (стили `MAP_<слой>_<0…4>` создаются сборкой:
  в защищённой книге стили менять нельзя); переключение слоя — одна запись сетки.
