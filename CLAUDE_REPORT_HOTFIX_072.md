## 1. Просрочки как статуса нет (D-089)

**Ядро (`WmsOrders`, версия `0.7.2-hotfix`):**
- `PositionStatus(заказано, получено, без документов, отмена)` — без даты: ничего не получено → «Ожидается» (и когда Q прошла);
  частично → «Частично получено» (и когда Q прошла); остаток отменён → «Частично получено / остаток отменён»; полностью —
  «Получено» / «Получено без документов»; заказ отменён — «Отменено». Все расчёты статуса в `WmsReceipt` (приход, «Ещё
  поступление», «Исправить», сторно, «Отменить заказ», «Отменить остаток», проверка строки, перенос) — без даты.
- Ввод строки заказа (`PreviewOrderRow`) и изменение Q после прихода статус не трогают: ветка по дате удалена.
- **«Обновить статусы» и запуск** (`RefreshStatuses`): дают статус строкам, введённым без макросов (W пуста), и переводят статусы по
  дате книг прежних версий («Просрочено», «Частично получено / просрочено» — книга 0.7.1, обновлённая 0.6, копия) в статусы по
  данным. Поиск кандидатов — движком Calc (`WordBlocks` по двум старым словам + пустые W), как и раньше без чтения всех строк.
  Сообщение: «статусы заказов: ожидаемых позиций N, из них с прошедшей ожидаемой датой M (статус от даты не зависит); обновлено
  статусов K (статусов по дате прежней версии пересчитано J)». Счёт M — формулами Calc (`COUNTIFS` в `ScratchEval`), без записи в
  книгу. Удалены: ветка «частично получено и просрочено» (`PartialDueRows`, `AddByDate`, `ExpectedDate`) и её тестовые швы
  (`TestRefreshMode`, `TestRefreshPath`).
- **Подсветка Q** (`tools/build_ods.py`): условное оформление `WMS_LateDate` на Q — дата прошла, а позиция «Ожидается» или «Частично
  получено». Ничего не пишет в книгу, считается по `TODAY()` при каждом пересчёте; статус, проведение и приходы не затрагивает.
  У Q своё условное оформление из трёх условий — «начало заказа и дата прошла» (`WMS_OrderStartLate`: линия блока и отметка), линия
  блока, отметка: оформление LibreOffice применяет только первое верное условие, и с одним общим правилом у первой строки каждого
  заказа отметка терялась бы под линией (нашёл полный регресс — M6 S01, S03; проверка отрисовки — новый S05).
- **«Приход авто»**: подсказка по поставщику — открытые позиции «Ожидается» / «Частично получено» (и старые статусы по дате), «из них
  ожидаемая дата прошла: N» — по Q.
- Константы `OS_OVERDUE`, `OS_PARTIAL_OVERDUE` остались только чтобы узнавать и пересчитывать статусы прежних версий.

**WMS_TOOLBOX 1.1.2** (новые общие функции `TbCommon.TbOpenStatus`, `TbDaysLate`, `TbLateFormula`):
- «Контроль дня»: пункт «Ожидаемая дата прошла» — «З-104 «Герметик» (Химпром) — на 37 дн.», уровень «Внимание», совет «Заказ ждём
  дальше: уточните сроки у поставщиков и закупок (статус от даты не меняется)». Напоминание, не статус.
- Аналитика — «Ожидаемая дата прошла (заказ ждём)»; отчёт руководителю — «Ожидаемая дата прошла, позиций (на день снимка; заказ
  ждём)»; Поиск (заказы поставщика) — «ожидается N, ожидаемая дата прошла M»; закономерности (`wms_insights.py`) — тот же пункт
  контроля с числом дней.
- Все считают по Q открытых позиций; снимок WMS до 0.7.2 со статусом «Просрочено» читается как открытая позиция (фикстура K05/K06
  снята с WMS 0.7.1 и такой статус содержит).

**Перенос старой таблицы** «Просрочено» не рассчитывает: старый текст «Просрочено» — открытый заказ, «Частично получено /
просрочено» — частично получено; «2_Проверка» — «С прошедшей ожидаемой датой (заказ ждём, статус не меняется)» вместо
«Просроченных».

**Совместимость:** схема книги, журнал и снимок не менялись. Книга 0.7.1 с её макросами работает как прежде (с просрочкой по
дате) — новые правила действуют в книгах выпуска 0.7.2; книга 0.6.0 после `tools/upgrade.py` получает ядро 0.7.2, и её статусы по
дате пересчитываются при первом запуске.

## 2. Старые статусы (W)

- **Реальные статусы пользователя (D-090):**
  - «Ожидает размещения» — открытый заказ, ещё не размещён: в WMS «Ожидается», в комментарий Z добавляется «Статус до переноса:
    Ожидает размещения» (смысл не теряется; П-70);
  - «Размещён» — открытый размещённый заказ: «Ожидается»;
  - «Ожидаем» — открытый заказ, поставку продолжаем ждать: «Ожидается»;
  - «Получен без документов» — товар физически получен, документов нет: «Получено без документов» (по количествам и документам);
  - «Отменён» — отменённый заказ: «Отменено».
  «Отменен» = «Отменён», «Размещен» = «Размещён», «  ожидаем », «ОЖИДАЕМ» — то же самое.
- **Сравнение:** нижний регистр, ё = е, знаки препинания — пробелы, один пробел, «/» с пробелами; «Заказ …» — как без слова «заказ»
  (`status_key`, `status_lookup`). «Размещен», «Размещён», «РАЗМЕЩЕН», «размещено», «Заказ размещён!», «  в пути » — всё понимается.
- **Таблица синонимов** (`STATUS_SYNONYMS` в `tools/legacy_transfer.py`; формы причастий — все роды и число):
  - заказ открыт (OPEN → «Ожидается»): размещен, заказан, оформлен, отгружен, оплачен, согласован, подтвержден; ожидается, ожидаем,
    ожидание, ждем, в пути, в заказе, не получено, в работе; ожидает размещения, к размещению, не размещен; старое «просрочено»,
    «просрочка»;
  - получено (RECEIVED): получен, оприходован, доставлен, поставлен, принят, выполнен, закрыт; получено полностью, поступило, на складе;
  - частично (PARTIAL): частично, частично получен / оприходован / поставлен…; старое «частично получено / просрочено»;
  - без документов: получен(о) без документов, без док, получено б/д…;
  - отменено (CANCELLED): отменен, аннулирован, снят (все формы), отмена, отказ, отказано, снят с заказа, отменён поставщиком / клиентом;
  - остаток отменён: частично получено / остаток отменён, остаток отменён.
- **Статус новой WMS не копируется:** его считает новый движок по количествам, приходам и документам (без даты, D-089); смысл
  старого статуса нужен только для отмены, для критических противоречий и для «старый → новый».
- **Старый текст — для аудита дословно:** LegacyStatus в журнале прихода (`LEGACY_STATUS`), в карте строк `LEGACY_ROWS.csv` (у
  каждой строки, и у ожидаемой) и в таблице «старый → новый» отчёта. Понятый синоним — нормализация в AE: «старый статус
  «Размещен» понят как «Ожидается»».
- **Неизвестный статус не блокирует:** жёлтое «W: неизвестный старый статус «…» — состояние рассчитано по данным: «…»»; в «2_Проверка»
  — счётчик «Неизвестные старые статусы (состояние рассчитано по данным)».
- **Блокер — только когда без смысла нельзя безопасно:** статус со словом отмены (отмен…, аннулир…, отказ…, снят…), которого нет в
  таблице («Отменить?», «Снят поставщиком»): отменена позиция целиком, только остаток или она ещё ожидается — не угадывается
  (счётчик «Статусы, похожие на отмену, но не из словаря»). Критические противоречия M7 остаются: статус «получено», а количества
  нет; «Отменено», а позиция получена полностью.
- **Свои синонимы статусов** — новая строка «Настройки» (15): `старый статус = смысл` через «;» (переносы строк в ячейке — тоже
  разделители). Смысл — статус WMS или слово таблицы (OPEN, RECEIVED, PARTIAL, CANCELLED; OVERDUE — как OPEN). Свой синоним
  сильнее таблицы (`Закрыто = Отменено`). Неверная запись — блокер «настройки» с объяснением. Правило входит в SHA-256 правил:
  изменение после создания тестовой WMS требует пересоздать и сверить её.
- Программа переноса 1.0.1 требует книгу-кандидат с ядром `0.7.2-hotfix` и новее: книга 0.7.1 считала бы просрочку по дате —
  понятный отказ «ядро книги-кандидата … не умеет переносить старую таблицу по правилам этого инструмента — нужна книга выпуска
  0.7.2 или новее».

## 3. Даты (N, O, P, Q)

- **`parse_legacy_date()`** — один разбор для всех дат: число и дата-время Calc (время отбрасывается); текст день-месяц-год с одним
  разделителем «.», «/» или «-» (`1.9.26`, `01.09.26`, `1.09.2026`, `01.09.2026`, `1/9/26`, `01/09/2026`, `1-9-26`, `01-09-2026`),
  пробелы вокруг значения и разделителей, «г.» в конце, время после даты; `2026-09-01`. Год из двух цифр — 20xx. Только 2000–2099.
- **Не путается с количеством и ценой:** число меньше 3653 (до 1910) — «число, а не дата»; «46266» текстом, «1.9» без года,
  смешанные разделители, «31.02.2026» — не даты; количества и цены по-прежнему не принимают текст-дату (`qty_value`, `price_value`).
- **Пустая дата** остаётся пустой — замечаний нет (поле необязательное).
- **Непонятная дата** — жёлтое замечание, дата пустая, исходный текст — в комментарии Z («Дата заказа: когда-то»); у прихода
  непонятная дата документа (O) — приход без даты документа («Получено без документов»).
- **Блокер — только где WMS нужна дата:** дата поступления (N) прихода и поступления (приход WMS без неё не проводится) — с
  подсказкой; правило «Нет даты поступления (N)» = ДАТА ДОКУМЕНТА берёт дату документа (жёлтое, исходный текст — в Z).
  **Специальный приход** переносится ЕИ без даты (`MIGRATE`), поэтому его дата поступления больше не обязательна.
- Ожидаемая дата Q переносится как информация: статус от неё не зависит.

## 6. На утверждение

- **П-68** Старый статус понимается по таблице синонимов (без регистра, ё/е, пробелов, знаков, «заказ …») и своим синонимам
  «Настроек»; неизвестный статус — предупреждение, состояние по данным; блокер — только статус, похожий на отмену, но не из таблицы,
  и критические противоречия M7. Слово «снят» — отмена.
- **П-69** Все даты читаются `parse_legacy_date` (день первым, год из двух цифр — 20xx, 2000–2099); непонятная дата —
  предупреждение, текст в Z; блокер — только дата поступления прихода (или правило «дата документа»); у специального прихода дата
  не обязательна. Заменяет часть П-64 («даты N и O — только настоящие даты»).
- **П-70** «Ожидает размещения» (заказ ещё не размещён) в WMS — «Ожидается»: отдельного статуса «не размещён» нет, смысл сохраняется
  пометкой «Статус до переноса: …» в комментарии Z и в LegacyStatus. Подсветка Q и число позиций с прошедшей ожидаемой датой — как
  «ненавязчивое предупреждение» D-089.
