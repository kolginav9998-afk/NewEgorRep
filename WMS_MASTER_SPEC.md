# WMS MASTER SPEC v0.3

**Дата:** 25.09.2026  
**Статус:** архитектура после P1–P4; готово к началу разработки ядра при подтверждении пользователя  
**Основа:** WMS MASTER SPEC v0.1 + утверждённые решения D-001… + CLAUDE_REPORT_P1_P4  
**Дополнено 25.09.2026:** решения D-039…D-044, утверждённые при приёмке Core Phase 2 «Выдачи» — §9, §16, §20, §21  
**Приоритеты:** целостность данных → производительность → надёжность → удобство → расширяемость

## 1. Решение по архитектуре

Release 1 строится на **LibreOffice Calc + LibreOffice Basic**.

Главный принцип:
- обычная операция O(1);
- никаких полных сканирований листов при приходе/выдаче/возврате;
- тяжёлые проверки только вручную/порциями;
- аналитика, отчёты, архивы и прочие тяжёлые задачи — отдельными ODS-инструментами;
- рабочая книга не должна бесконечно расти.

P1–P4 прошли PASS WITH CONDITIONS. Архитектурных блокеров нет.

## 2. Неизменяемые интерфейсы

### `Заказы` A:AB
A № заказа; B Полное наименование товара; C Номер документа; D Номер счёта; E Артикул; F Фактическое количество; G Количество по документу; H Заказанное количество; I Единица измерения; J Цена; K Сумма; L Площадка / Поставщик; M Продавец; N Дата поступления; O Дата документа; P Дата заказа; Q Ожидаемая дата поступления; R Покупатель; S Категория; T Кому назначено; U Место хранения; V Внутренний код; W Статус; X Наличие; Y Контроль; Z Комментарий; AA Срок поставки, дней; AB Возможный дубль.

### `Выдачи` A:R
A №; B № документа выдачи; C Наименование; D Артикул; E Количество; F Количество в %; G Единица измерения; H Дата выдачи; I Кому выдано; J Место хранения; K Категория; L Внутренний код; M Вернул; N Вернул в %; O Комментарий; P Остаток до выдачи; Q Остаток после выдачи; R Контроль.

Новые служебные колонки сюда не добавляются.

## 3. Среда

- Один основной пользователь.
- Рабочая система: Ubuntu + LibreOffice.
- Работа полностью офлайн.
- Дополнительное ПО на рабочий компьютер не устанавливается.
- Исходники Basic хранятся текстом в GitHub.
- ODS — релизный артефакт, не единственный источник кода.

## 4. ЕИ

Канонический формат: `ЕИ-00000001`.

`Заказы.V` и `Выдачи.L` — ЕИ.

Нормализуются варианты:
- `7`
- `00000007`
- `ЕИ-7`
- `EI-7`
- смешанные допустимые варианты кириллицы/латиницы

в один канонический код.

Правила:
- существующие физические ЕИ не меняются;
- номер не переиспользуется;
- новый ЕИ только после безопасного максимального;
- обычный отдельный фактический приход → новый ЕИ;
- одинаковые обычные товары не ищутся и не объединяются;
- `Детали` — исключение: один основной ЕИ на уникальный артикул;
- выдача строго по введённому ЕИ;
- другой ЕИ автоматически не подбирается.

## 5. `Наличие`

`Наличие` — постоянный реестр ЕИ.

Одна строка = один ЕИ.

**Плотная адресация:** номер строки реестра вычисляется из номера ЕИ. Полный индекс ЕИ в памяти не строится.

Физическая сортировка реестра запрещена. Фильтрация допустима.

## 6. Заказы и частичные приходы

- исходная строка позиции содержит `H Заказанное количество`;
- первый приход может заполнить исходную строку;
- следующий УПД той же позиции → дополнительная строка;
- в дополнительной строке H пустая;
- A и D сохраняют тот же заказ/счёт;
- связь дополнительной строки с исходной позицией хранится служебно;
- каждый обычный отдельный приход получает новый ЕИ.

### Контроль количества
- G = F → нормально;
- G > F → недостача;
- G < F → излишек.

### Документы
- счёт без факта → ожидается;
- факт без закрывающего документа → получено без документов;
- факт + закрывающий документ → получено.

### Отмена
- полный заказ;
- остаток после частичного прихода.

Исходное H не переписывается.

## 7. Специальные приходы

Значения `Площадка / Поставщик`:
- Офис
- Производство
- Детали
- Старый склад

Авто-ID:
- OFF-
- PROD-
- DET-
- OLD-

Один ID относится к одной фактической приёмке, даже если в ней несколько строк.

## 8. Детали

- артикул уникален;
- существующий артикул → подставить ЕИ + название;
- новый артикул → новое название + новый ЕИ;
- повторный приход увеличивает количество существующего ЕИ;
- старые конфликты «несколько ЕИ на один артикул» решаются миграционно без перенумерации.

## 9. Выдачи

Быстрый сценарий:
`ЕИ → количество → кому → Провести`.

Подстановка:
- название;
- артикул;
- ед.;
- место;
- категория;
- остаток.

Блок:
- ЕИ не найден;
- остаток 0;
- количество > остатка;
- заполнена F `Количество в %` — пока правила процентной выдачи не утверждены, заполненная F блокирует проведение (D-043).

`P/Q` — снимок на момент проведения, не живая историческая цепочка.

Удаление выдачи = статус `Удалено (сторно)`. Строка остаётся с № и данными, заблокирована, № не переиспользуется (D-039).

Исправление выдачи = одна составная операция `ISSUE_FIX` (D-040): сторно старого движения и новое движение — одна операция `ApplyOperation` и одна строка журнала.

## 10. Получатели

Свободный текст разрешён.

Отдельный справочник сокращений:
`егр` → полное ФИО.

AutoInput Calc при работе WMS **выключается**, иначе он вмешивается в сокращения.

Получатель вне справочника → предупреждение, не обязательная ошибка.

## 11. Возвраты

Отдельный лист `Возврат`.

Поля как минимум:
- № возврата
- дата
- ЕИ
- количество
- кто принёс
- на чью выдачу засчитать
- место
- авто-наименование
- авто-единица
- контроль
- комментарий

Поддерживаются частичные и многократные возвраты.

`Выдачи.M/N` остаются legacy/информационными. Новые возвраты туда не распределяются.

## 12. Ввод количества — ОБЯЗАТЕЛЬНЫЙ контракт

Ввод не должен зависеть от локали LibreOffice.

Рекомендуемая схема:
- вводимые ячейки количества временно текстовые;
- строгий разбор WMS;
- разрешить `1,5` и `1.5`;
- максимум 3 знака после разделителя;
- запретить даты, отрицательные, экспоненты, `1 000`, неоднозначные записи;
- после успешного проведения записать нормальное числовое значение;
- `MAX_QTY` как второй защитный порог.

Это обязательно до пилота.

## 13. Лёгкие обработчики

Разрешены лёгкие реакции:
- ЕИ → предпросмотр;
- артикул детали → ЕИ/название;
- сокращение → ФИО.

Они:
- не сканируют лист;
- мгновенно выходят для чужих колонок;
- защищены от re-entry;
- отключаются в Safe Mode.

При вставке/заполнении нескольких строк предпросмотр обновляется для всех затронутых строк.

## 14. Идентичность строк

### `Выдачи`
A `№` выдаёт только WMS.

### `Заказы`
V = ЕИ обычного прихода.
Для деталей служебно используется DET-ID.

### `Возврат`
A = системный номер возврата.

Номер физической строки — только подсказка. Перед использованием он проверяется по ключу. Запасной поиск — одной C++-формулой MATCH, не циклом Basic.

## 15. Копии и подделанные строки

Строка считается копией/подозрительной если:
- ключ повторяется;
- либо ключ существует в строке, но WMS его никогда не выдавала.

Такая строка:
- помечается `КОПИЯ`;
- не проводится;
- очищается отдельной командой `Очистить копию`.

Заполнение маркером/FillSeries не должно создавать «проведённые» строки.

## 16. Защита

После проведения:
- учётные ячейки блокируются;
- фильтр разрешён;
- вставка строк разрешена;
- сортировка и ручное удаление проведённых строк запрещены;
- пароль не используется в обычной работе.

Для непроведённой строки `Выдачи` защищены A, C, D, G, J, K, P, Q, R (D-042).

Диапазон автофильтра должен автоматически расширяться ядром.

При сохранении с активным фильтром WMS временно снимает скрытие строк, не удаляя условия фильтра, сохраняет книгу и затем восстанавливает фильтр (D-041). Причина: LibreOffice 24.2 открывает файл с большим числом скрытых фильтром строк за квадратичное время. Условия фильтра WMS применяет снова и при следующем запуске.

## 17. Undo

На время любой учётной операции Undo блокируется.

После успешного проведения стек Undo очищается.

Пользователь должен знать: после `Провести` предыдущий ручной ввод через Ctrl+Z уже не восстанавливается.

## 18. Двухфазное проведение — ЕДИНСТВЕННЫЙ путь записи

### Фаза 1
Все проверки, нормализация и расчёты без изменений документа.

### Фаза 2
1. STARTED + before-image;
2. точечная запись;
3. **строка внешнего журнала — точка фиксации**;
4. COMMITTED + LAST_SEQ.

До записи журнала ошибка → полный откат.
После записи журнала → только доведение операции.

Одна функция `ApplyOperation` используется для:
- обычного проведения;
- recovery/replay;
- сторно;
- исправления.

## 19. Before-image

Служебные данные внутри ячеек хранятся только печатными символами.

Никаких управляющих Chr(30)/Chr(31) и подобных разделителей, которые ODS может потерять.

Формат должен пройти тест:
`записать → сохранить → закрыть → открыть → прочитать`.

## 20. Внешний журнал

Папка: `WMS_Journal/`

Формат строки:
`J1;seq;время;экземпляр;тип;поля...;END;длина`

Правила:
- UTF-8;
- LF;
- файл на месяц;
- только append;
- seq строго непрерывный;
- разрыв seq → STOP;
- перед append проверяется владение/размер файла;
- внешний процесс изменил журнал → STOP.

Позиция журнала в книге:
`файл|смещение|seq`

Перед использованием она проверяется по содержимому (D-044):
- обычный startup использует подтверждённую сохранённую позицию и читает только необходимый хвост;
- если позиция не подтверждена, сначала читается соответствующий месячный файл;
- полный исторический журнал читается только как fallback;
- полный self-check всего журнала является отдельной диагностической операцией, а не частью обычного запуска.

## 21. Fail-closed запуск

Любая ошибка запуска или несогласованность блокирует проведение.

Разрешённые явные действия:
- `Восстановить`;
- `Отложить хвост журнала`;
- `Снять блокировку WMS`;
- `Сделать рабочим файлом`.

Нельзя «продолжить как будто всё нормально».

Полный self-check всего журнала в обычный запуск не входит — это отдельная диагностика (D-044, §20).

## 22. Блокировка WMS

Используется lock-файл рядом с журналом.

Lock принадлежит конкретному экземпляру WMS и снимается по владельцу.

Копия/backup WMS, открытая напрямую, не может проводить операции, пока явно не выполнено `Сделать рабочим файлом`.

## 23. Непроведённые строки

Подсчёт выполняется по всему листу одной быстрой формулой.

`Провести все` может работать по рабочему окну, но строка вне окна обязана появиться в отчёте запуска.

## 24. Полные проверки

Никакого чтения 18–30 колонок на сотнях тысяч строк одним огромным массивом.

Проверки идут:
- только по нужным колонкам;
- блоками примерно по 20 000 строк;
- с ограничением памяти.

## 25. Поиски и агрегаты

Для больших диапазонов:
- MATCH;
- COUNTIF/COUNTIFS;
- SUMIF/SUMIFS;
- SUMPRODUCT

через движок Calc.

Не:
- `findFirst` как основной путь;
- длинные циклы Basic;
- полный EnumerableMap по всему реестру.

Индекс деталей — маленький и ленивый.

## 26. Резервные копии

Папка: `WMS_Backups/`

- одна автоматическая дневная;
- перед обновлением;
- перед миграцией;
- ручная кнопка;
- ротация;
- периодическая копия backups + journal на другой носитель рекомендована.

## 27. Размер рабочей книги

Ориентир: **не более ~250k движений**.

Точный предел определяется на реальном рабочем ПК.

До миграции обязательно повторить P2 на:
- рабочем Ubuntu;
- копии реальной книги;
- с реальными стилями/фильтрами/условным форматированием.

Если прогноз стартовый объём + 2–3 года приближается к 200–250k — архивирование нельзя откладывать.

## 28. Архив

Архивируется история, но не ЕИ.

Все ЕИ остаются в постоянном реестре.

Возвращённый архивный ЕИ снова активируется.

Архивирование запускается явно и проверяемо.

## 29. Настройки LibreOffice

Перед пилотом:
- папка WMS добавляется в доверенные расположения;
- безопасность макросов не снижается ниже необходимого;
- AutoInput управляется WMS;
- интервал автосохранения подбирается с учётом фактического времени сохранения;
- формат ODS обязателен.

## 30. Отключённые макросы

Если книга сохранялась/изменялась без WMS:
- следующий запуск это обнаруживает;
- выполняется полная проверка порциями;
- неизвестные/поддельные ключи выявляются до проведения.

Ошибка компиляции любого модуля Basic также должна приводить к fail-closed состоянию.

## 31. Миграция

Существующие 500+ ЕИ сохраняются.

До production:
- dry-run;
- инвентаризация ЕИ;
- максимальный номер;
- дубли;
- конфликты;
- старые детали;
- бумажные выдачи;
- сверка;
- выборочные физические наклейки;
- rollback.

## 32. Производительность

Цель обычной операции ≤ 0,5 с на рабочем ПК.

Облачные P1–P4 показали большой запас по ежедневным операциям, но скорость открытия/сохранения сильно зависит от железа.

До миграции результат на реальном Ubuntu обязателен.
