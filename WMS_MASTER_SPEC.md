## 1. Решение по архитектуре

Release 1 строится на **LibreOffice Calc + LibreOffice Basic**.

Главный принцип:
- обычная операция O(1);
- никаких полных сканирований листов при приходе/выдаче/возврате;
- тяжёлые проверки только вручную/порциями;
- аналитика, отчёты, архивы и прочие тяжёлые задачи — отдельными ODS-инструментами;
- рабочая книга не должна бесконечно расти.

P1–P4 прошли PASS WITH CONDITIONS. Архитектурных блокеров нет.

## 2. Неизменяемые интерфейсы

### `Заказы` A:AB
A № заказа; B Полное наименование товара; C Номер документа; D Номер счёта; E Артикул; F Фактическое количество; G Количество по документу; H Заказанное количество; I Единица измерения; J Цена; K Сумма; L Площадка / Поставщик; M Продавец; N Дата поступления; O Дата документа; P Дата заказа; Q Ожидаемая дата поступления; R Покупатель; S Категория; T Кому назначено; U Место хранения; V Внутренний код; W Статус; X Наличие; Y Контроль; Z Комментарий; AA Срок поставки, дней; AB Возможный дубль.

### `Выдачи` A:R
A №; B № документа выдачи; C Наименование; D Артикул; E Количество; F Количество в %; G Единица измерения; H Дата выдачи; I Кому выдано; J Место хранения; K Категория; L Внутренний код; M Вернул; N Вернул в %; O Комментарий; P Остаток до выдачи; Q Остаток после выдачи; R Контроль.

Новые служебные колонки сюда не добавляются.

## 4. ЕИ

Канонический формат: `ЕИ-00000001`.

`Заказы.V` и `Выдачи.L` — ЕИ.

Нормализуются варианты:
- `7`
- `00000007`
- `ЕИ-7`
- `EI-7`
- смешанные допустимые варианты кириллицы/латиницы

в один канонический код.

Правила:
- существующие физические ЕИ не меняются;
- номер не переиспользуется;
- новый ЕИ только после безопасного максимального;
- обычный отдельный фактический приход → новый ЕИ;
- одинаковые обычные товары не ищутся и не объединяются;
- `Детали` — исключение: один основной ЕИ на уникальный артикул;
- выдача строго по введённому ЕИ;
- другой ЕИ автоматически не подбирается.

## 5. `Наличие`

`Наличие` — постоянный реестр ЕИ.

Одна строка = один ЕИ.

**Плотная адресация:** номер строки реестра вычисляется из номера ЕИ. Полный индекс ЕИ в памяти не строится.

Физическая сортировка реестра запрещена. Фильтрация допустима.

ЕИ обычного прихода: состояние «Активен», после сторно прихода — «Приход удалён (сторно)»; источник — «Заказ <№ заказа>» (D-053).

Место ЕИ («Наличие».F) меняется только операцией перемещения `MOVE`, остаток вне приходов, выдач и возвратов — только списанием `WRITE_OFF` и инвентаризационной корректировкой `INV_ADJ` (лист «Корректировки», Final Core; правила — `CLAUDE_REPORT_FINAL_CORE.md`, П-1…П-8, на утверждении). Тихого изменения места и остатка нет.

## 6. Заказы и частичные приходы

- исходная строка позиции содержит `H Заказанное количество`;
- первый приход может заполнить исходную строку;
- следующий УПД той же позиции → дополнительная строка;
- в дополнительной строке H пустая;
- A и D сохраняют тот же заказ/счёт;
- связь дополнительной строки с исходной позицией хранится служебно;
- каждый обычный отдельный приход получает новый ЕИ;
- в дополнительную строку копируются A, D и B, E, I, L, M, P, R, S, T, J исходной строки; H, K, Q, Z, AA не копируются — Q (ожидание позиции) живёт в исходной строке (D-052).

### Обязательные поля прихода (D-048)
A № заказа, B наименование, H заказанное > 0, I единица, F факт > 0, N дата поступления, U место. Приход без строки заказа с H (товар без заказа) обычным приходом не проводится — это «Иной приход» следующих этапов или новая строка заказа.

### Дата поступления N (D-049)
- N обязательна;
- первый приход из исходной строки: дата не подставляется молча — пустая N блокирует проведение;
- окно «Ещё поступление»: N предварительно заполнена сегодняшней датой как предложение, пользователь может изменить её перед подтверждением;
- будущие диалоговые сценарии прихода, где это уместно: дата по умолчанию = сегодня, но не скрытая автоматическая фиксация.

### Контроль количества
- G = F → нормально;
- G > F → недостача;
- G < F → излишек.

### Документы
- счёт без факта → ожидается;
- факт без закрывающего документа → получено без документов;
- факт + закрывающий документ → получено.

Документ считается внесённым, когда заполнены и C (номер), и O (дата) (D-045). Документ добавляется позднее через «Исправить» (C, O, G после проведения закрыты): одна операция журнала, ЕИ тот же, нового прихода нет (D-046).

### Статусы позиции (D-089; до 0.7.2 — D-047)
Статус — у позиции, показывается в W исходной строки. Q — ожидаемая дата. **Статус от даты не зависит** (D-089):
- ничего не получено → `Ожидается` (в том числе когда Q прошла);
- частично получено, остаток не отменён → `Частично получено` (в том числе когда Q прошла);
- остаток отменён → `Частично получено / остаток отменён`;
- получено полностью → `Получено` или `Получено без документов`;
- заказ отменён → `Отменено`.

Система ждёт поставку до получения или ручной отмены. `Просрочено` и `Частично получено / просрочено` не появляются ни при вводе, ни при открытии, ни при «Обновить статусы», ни после переноса; такие статусы книги прежней версии при открытии и кнопкой «Обновить статусы» становятся статусами по данным.

Q — информация, аналитика и контроль сроков: если ожидаемая дата прошла, а позиция ещё ждётся, Q подсвечивается (условное оформление, ни на что не влияет); сообщение «Обновить статусы» и отчёт запуска называют число таких позиций; инструменты показывают «Ожидаемая дата прошла на N дн.».

Y исходной строки показывает, сколько осталось получить. «Обновить статусы» (и открытие) дают статус строкам, введённым без макросов, — без тяжёлого пересчёта листа.

### Отмена
- полный заказ;
- остаток после частичного прихода.

Исходное H не переписывается.

Полностью отменённая позиция («Отменено») окончательна: приход по ней не проводится, «вернуть» её нельзя — новая строка заказа; отменить заказ можно, пока по позиции нет действующих приходов, в том числе после сторно всех приходов (D-050). Поступление по позиции с отменённым остатком разрешено («Ещё поступление»): статус пересчитывается (D-051).

### Антидубль (D-054)
Ключ: поставщик + номер документа + артикул (или название) + факт F + дата документа O (или дата поступления N), с нормализацией написания. Только предупреждение (AB); сторнированные приходы не учитываются.

### Цена и сумма (D-055)
Цена J: число ≥ 0 (0 допустим), до 3 знаков после запятой; после проведения закрыта и исправляется через «Исправить». K «Сумма» — информационное поле пользователя.

### Проведение блока строк (D-059)
Каждая видимая строка с F проводится отдельной атомарной операцией:
- строка без F пропускается;
- обычная ошибка валидации одной строки не останавливает остальные строки блока;
- результат показывает, сколько строк проведено, сколько пропущено и сколько отклонено с ошибкой;
- любая системная ошибка WMS — ошибка журнала, recovery, блокировка/fail-closed, ошибка `ApplyOperation`, повреждение состояния или невозможность гарантировать атомарность — немедленно прекращает дальнейшую обработку всего блока; пакет после системной ошибки не продолжается.

### Сторно прихода (D-069)
Сторно прихода (`RECEIPT_DEL`) запрещено, если по его ЕИ существуют действующие выдачи (и возвраты), — независимо от того, полностью ли они возвращены. Порядок для пользователя:
1. сторнировать действующие возвраты этого ЕИ;
2. сторнировать связанные выдачи;
3. только после отсутствия действующих зависимых движений — сторно прихода.

После `RECEIPT_DEL` не остаётся действующей исторической цепочки «выдача → возврат», ссылающейся на сторнированный приход. Исторические строки сторнированных операций остаются, номера не переиспользуются. Отказ — понятным сообщением («По этому ЕИ есть связанные выдачи/возвраты… Сначала выполните сторно зависимых операций»). Проверка — без полного прохода по листам: одна формула движка Calc (COUNTIFS) по занятым строкам «Выдач» (ЕИ + «Проведено» / «Проведено (исправлено)») и `_RET` (ЕИ + действующий возврат). Прежнее правило остатка (остаток ЕИ = количеству прихода) сохраняется как дополнительная защита.

Кнопка «Удалить» прихода: сначала проверяется, разрешено ли `RECEIPT_DEL` (все проверки сторно, включая D-069); при отказе сразу показывается причина, окно подтверждения не открывается; подтверждение «Удалить приход?» — только если сторно допустимо; после подтверждения выполняется операция (уточнение пользователя к D-069).

## 7. Специальные приходы

Один лист «Иной приход» с колонкой «Тип прихода» (D-071); № события — префикс + 8 цифр, свой счётчик на тип (D-073):
- Офис — `OFF-`;
- Производство — `PROD-`;
- Детали — `DET-`;
- Старый склад — `OLD-`;
- Иной (неопознанный товар) — `OTH-`.

Один № события относится к одной фактической приёмке, даже если в ней несколько строк: выделенные строки → «Провести как одно поступление?» (D-074). № строки листа — отдельный счётчик `NEXT_SPL`.

- «Заказы» — только обычные заказы; товар без заказа — «Иной приход» (D-048, D-071).
- ЕИ создаётся при проведении; «Наличие».J «Тип источника», I «Источник» — «<тип> <№ события>» (D-082).
- «Иной» → ЕИ «Требует разбора»: считается остатком, выдаётся и возвращается. «Разобрать» уточняет карточку того же ЕИ; тип выбирается явно, значения по умолчанию нет, «OK» без выбора — отказ (D-080, D-081).
- Исправление (D-079), сторно (D-078), статусы строки (D-088), антидубль — только предупреждение (D-085), старая маркировка — в строке и журнале (D-084), O/P — снимок остатка (D-086).

Журнал: `SP_RECEIPT`, `SP_REFILL`, `SP_FIX`, `SP_DEL`, `SP_IDENTIFY`. Служебные таблицы: `_SPR` (строки листа по №), `_ART` (индекс «нормализованный артикул → ЕИ»).

## 8. Детали

- артикул уникален;
- существующий артикул → подставить ЕИ + название;
- новый артикул → новое название + новый ЕИ;
- повторный приход увеличивает количество существующего ЕИ;
- старые конфликты «несколько ЕИ на один артикул» решаются миграционно без перенумерации.
- артикул сравнивается после нормализации (D-075); индекс `_ART`, перестройка — макрос `ArticleIndexRebuild` (D-083);
- повторный приход: карточка из ЕИ, единица должна совпасть (D-076); другое место — перемещение ЕИ с подтверждением строки (D-077).

## 9. Выдачи

Быстрый сценарий:
`ЕИ → количество → кому → Провести`.

Подстановка:
- название;
- артикул;
- ед.;
- место;
- категория;
- остаток.

Блок:
- ЕИ не найден;
- остаток 0;
- количество > остатка;
- заполнена F `Количество в %` — пока правила процентной выдачи не утверждены, заполненная F блокирует проведение (D-043).

`P/Q` — снимок на момент проведения, не живая историческая цепочка.

Удаление выдачи = статус `Удалено (сторно)`. Строка остаётся с № и данными, заблокирована, № не переиспользуется (D-039).

Исправление выдачи = одна составная операция `ISSUE_FIX` (D-040): сторно старого движения и новое движение — одна операция `ApplyOperation` и одна строка журнала.

Выдача с действующими возвратами (§11):
- `ISSUE_FIX` меняет только количество: не ниже возвращённого, больше — при достаточном остатке; ЕИ, получатель и дата выдачи меняются только после сторно этих возвратов (D-063);
- `ISSUE_DEL` запрещён, пока есть действующие возвраты: сначала сторно возвратов; обратные возвраты автоматически не создаются.

## 11. Возвраты

Отдельный лист `Возврат`.

Поля как минимум:
- № возврата
- дата
- ЕИ
- количество
- кто принёс
- на чью выдачу засчитать
- место
- авто-наименование
- авто-единица
- контроль
- комментарий

Поддерживаются частичные и многократные возвраты.

`Выдачи.M/N` остаются legacy/информационными. Новые возвраты туда не распределяются.

Реализация Core Phase 4 — лист «Возврат» A:O (A № возврата, B № выдачи, C ЕИ, D наименование, E артикул, F количество, G единица, H дата возврата, I от кого возвращено, J место, K категория, L остаток до, M остаток после, N контроль/статус, O комментарий), служебные таблицы `_RET` (возвраты по №) и `_ISS` (итоги возвратов выдачи по № выдачи):
- **связь с выдачей** — только по № конкретной проведённой выдачи (ключ «Выдачи».A), не по «ЕИ + получатель + количество»; номер строки — подсказка, проверяемая ключом, запасной поиск — MATCH движка Calc;
- **тот же ЕИ:** возврат увеличивает остаток ЕИ выдачи в «Наличие» (и «Заказы».X этого ЕИ); новый ЕИ не создаётся; возврат при остатке 0 разрешён;
- **доступно к возврату** = количество выдачи − сумма действующих возвратов этой выдачи; несколько выдач одного ЕИ независимы;
- **номер возврата** — отдельный счётчик `NEXT_RET` в `_SYS`: монотонный, не переиспользуется (D-060);
- **кто возвращает** — только получатель исходной выдачи; другой получатель — отказ, передача между получателями — будущий сценарий; правило v0.1 §20 («вернуть может и другой человек», «возврат не обязан связываться с конкретной строкой выдачи») не действует (D-061);
- **дата возврата** обязательна, не раньше даты выдачи; окно «Найти выдачу» предлагает сегодняшнюю, пользователь может изменить (D-062);
- **место:** другое место в J перемещает ЕИ в той же операции возврата, «Контроль» заранее предупреждает (D-065); сторно возврата место не возвращает (D-064);
- **единица** — единица выдачи; другая единица ЕИ в реестре — отказ, пересчёт единиц — отдельный этап (D-070);
- **исправление** (`RETURN_FIX`, одна составная операция) меняет количество, дату и место; выдача и ЕИ те же; другая выдача — сторно и новый возврат (D-066);
- **сторно** (`RETURN_DEL`): строка остаётся историей «Удалено (сторно)», № не переиспользуется; запрещено, если остаток ЕИ станет отрицательным;
- возврат по удалённой (сторно) выдаче запрещён; выдачи с действующими возвратами — §9 (D-063); сторно прихода при действующих выдачах/возвратах его ЕИ — §6 (D-069);
- **«Найти выдачу»** показывает не больше 100 последних выдач ЕИ, которые ещё можно вернуть; более старую вводят по № в B (D-067).

## 12. Ввод количества — ОБЯЗАТЕЛЬНЫЙ контракт

Ввод не должен зависеть от локали LibreOffice.

Рекомендуемая схема:
- вводимые ячейки количества временно текстовые;
- строгий разбор WMS;
- разрешить `1,5` и `1.5`;
- максимум 3 знака после разделителя;
- запретить даты, отрицательные, экспоненты, `1 000`, неоднозначные записи;
- после успешного проведения записать нормальное числовое значение;
- `MAX_QTY` как второй защитный порог.

Это обязательно до пилота.

## 13. Лёгкие обработчики

Разрешены лёгкие реакции:
- ЕИ → предпросмотр;
- артикул детали → ЕИ/название;
- сокращение → ФИО.

Они:
- не сканируют лист;
- мгновенно выходят для чужих колонок;
- защищены от re-entry;
- отключаются в Safe Mode.

При вставке/заполнении нескольких строк предпросмотр обновляется для всех затронутых строк.

## 14. Идентичность строк

### `Выдачи`
A `№` выдаёт только WMS.

### `Заказы`
V = ЕИ обычного прихода.
Для деталей служебно используется DET-ID.

### `Возврат`
A = системный номер возврата (счётчик `NEXT_RET`, D-060). Регистрация — `_RET` (плотно по №); итоги возвратов выдачи — `_ISS` (плотно по № выдачи).

Номер физической строки — только подсказка. Перед использованием он проверяется по ключу. Запасной поиск — одной C++-формулой MATCH, не циклом Basic.

## 15. Копии и подделанные строки

Строка считается копией/подозрительной если:
- ключ повторяется;
- либо ключ существует в строке, но WMS его никогда не выдавала.

Такая строка:
- помечается `КОПИЯ`;
- не проводится;
- очищается отдельной командой `Очистить копию`.

Заполнение маркером/FillSeries не должно создавать «проведённые» строки.

## 16. Защита

После проведения:
- учётные ячейки блокируются;
- фильтр разрешён;
- вставка строк разрешена;
- сортировка и ручное удаление проведённых строк запрещены;
- пароль не используется в обычной работе.

Для непроведённой строки `Выдачи` защищены A, C, D, G, J, K, P, Q, R (D-042).

Диапазон автофильтра должен автоматически расширяться ядром.

При сохранении с активным фильтром WMS временно снимает скрытие строк, не удаляя условия фильтра, сохраняет книгу и затем восстанавливает фильтр (D-041). Причина: LibreOffice 24.2 открывает файл с большим числом скрытых фильтром строк за квадратичное время. Условия фильтра WMS применяет снова и при следующем запуске.

## 17. Undo

На время любой учётной операции Undo блокируется.

После успешного проведения стек Undo очищается.

Пользователь должен знать: после `Провести` предыдущий ручной ввод через Ctrl+Z уже не восстанавливается.

## 18. Двухфазное проведение — ЕДИНСТВЕННЫЙ путь записи

### Фаза 1
Все проверки, нормализация и расчёты без изменений документа.

### Фаза 2
1. STARTED + before-image;
2. точечная запись;
3. **строка внешнего журнала — точка фиксации**;
4. COMMITTED + LAST_SEQ.

До записи журнала ошибка → полный откат.
После записи журнала → только доведение операции.

Одна функция `ApplyOperation` используется для:
- обычного проведения;
- recovery/replay;
- сторно;
- исправления.

## 19. Before-image

Служебные данные внутри ячеек хранятся только печатными символами.

Никаких управляющих Chr(30)/Chr(31) и подобных разделителей, которые ODS может потерять.

Формат должен пройти тест:
`записать → сохранить → закрыть → открыть → прочитать`.

## 20. Внешний журнал

Папка: `WMS_Journal/`

Формат строки:
`J1;seq;время;экземпляр;тип;поля...;END;длина`

Правила:
- UTF-8;
- LF;
- файл на месяц;
- только append;
- seq строго непрерывный;
- разрыв seq → STOP;
- перед append проверяется владение/размер файла;
- внешний процесс изменил журнал → STOP.

Позиция журнала в книге:
`файл|смещение|seq`

Перед использованием она проверяется по содержимому (D-044):
- обычный startup использует подтверждённую сохранённую позицию и читает только необходимый хвост;
- если позиция не подтверждена, сначала читается соответствующий месячный файл;
- полный исторический журнал читается только как fallback;
- полный self-check всего журнала является отдельной диагностической операцией, а не частью обычного запуска.

## 21. Fail-closed запуск

Любая ошибка запуска или несогласованность блокирует проведение.

Разрешённые явные действия:
- `Восстановить`;
- `Отложить хвост журнала`;
- `Снять блокировку WMS`;
- `Сделать рабочим файлом`.

Нельзя «продолжить как будто всё нормально».

`Отложить хвост журнала` поднимает NEXT_EI и NEXT_NO выше номеров отложенных операций: номер, который уже мог попасть на наклейку или в документ, повторно не выдаётся (D-058). Так же поднимается `NEXT_RET` — выше № отложенных возвратов (D-060).

Полный self-check всего журнала в обычный запуск не входит — это отдельная диагностика (D-044, §20).

## 22. Блокировка WMS

Используется lock-файл рядом с журналом.

Lock принадлежит конкретному экземпляру WMS и снимается по владельцу.

Копия/backup WMS, открытая напрямую, не может проводить операции, пока явно не выполнено `Сделать рабочим файлом`.

## 23. Непроведённые строки

Подсчёт выполняется по всему листу одной быстрой формулой.

`Провести все` может работать по рабочему окну, но строка вне окна обязана появиться в отчёте запуска.

Проведение выделенного блока строк «Заказов» — по правилу D-059 (§6): каждая строка — своя операция, системная ошибка WMS останавливает весь блок. То же правило — для блока строк «Возврата» (Core Phase 4). Непроведённые строки «Возврата» (количество без №) показываются на «Главной» вместе с «Выдачами» и «Заказами».

## 24. Полные проверки

Никакого чтения 18–30 колонок на сотнях тысяч строк одним огромным массивом.

Проверки идут:
- только по нужным колонкам;
- блоками примерно по 20 000 строк;
- с ограничением памяти.

## 25. Поиски и агрегаты

Для больших диапазонов:
- MATCH;
- COUNTIF/COUNTIFS;
- SUMIF/SUMIFS;
- SUMPRODUCT

через движок Calc.

Не:
- `findFirst` как основной путь;
- длинные циклы Basic;
- полный EnumerableMap по всему реестру.

Индекс деталей — маленький и ленивый.

## 26. Резервные копии

Папка: `WMS_Backups/`

- одна автоматическая дневная;
- перед обновлением;
- перед миграцией;
- ручная кнопка;
- ротация;
- периодическая копия backups + journal на другой носитель рекомендована.

## 27. Размер рабочей книги

Ориентир: **не более ~250k движений**.

Точный предел определяется на реальном рабочем ПК.

До миграции обязательно повторить P2 на:
- рабочем Ubuntu;
- копии реальной книги;
- с реальными стилями/фильтрами/условным форматированием.

Если прогноз стартовый объём + 2–3 года приближается к 200–250k — архивирование нельзя откладывать.

## 28. Архив

Архивируется история, но не ЕИ.

Все ЕИ остаются в постоянном реестре.

Возвращённый архивный ЕИ снова активируется.

Архивирование запускается явно и проверяемо.

## 29. Настройки LibreOffice

Перед пилотом:
- папка WMS добавляется в доверенные расположения;
- безопасность макросов не снижается ниже необходимого;
- AutoInput управляется WMS;
- интервал автосохранения подбирается с учётом фактического времени сохранения;
- формат ODS обязателен.

Проверка этих настроек — кнопка «Проверка перед работой» на «Главной» (версия LibreOffice, уровень безопасности макросов и доверенное расположение, запись журнала и копий, автосохранение документа, размер книги, защиты: листы кроме «Получатели» защищены, служебные скрыты, структура книги защищена — иначе предупреждение); «Состояние системы» — версии, рабочий файл, журнал, копии (M3).

## 30. Отключённые макросы

Если книга сохранялась/изменялась без WMS:
- следующий запуск это обнаруживает;
- выполняется полная проверка порциями;
- неизвестные/поддельные ключи выявляются до проведения.

Ошибка компиляции любого модуля Basic также должна приводить к fail-closed состоянию.

## 31. Миграция

Существующие 500+ ЕИ сохраняются.

Миграция реальных старых ЕИ, остатков и истории — отдельный этап (D-057). Книга Phase 2 не обновляется до Phase 3 отдельным инструментом: ручная проверка и пилот начинаются с новой актуальной книги Phase 3. Книга Phase 3 так же не обновляется до Phase 4: ядро Phase 4 её не открывает (нет листов «Возврат», `_RET`, `_ISS`), ручная проверка и пилот возвратов — с новой книги Phase 4 (D-068).
Книга Phase 4 не обновляется до Phase 5: схема `_SYS` `WMS-SYS-2` (D-072).

Перенос выполняется операцией ядра `MIGRATE` (одна на строку таблицы переноса, прежний номер ЕИ без перенумерации, NEXT_EI выше номера, журнал хранит происхождение «файл | SHA-256 | строка»; П-11) — через импортёр DRY RUN → MIGRATE COPY → VERIFY → PROMOTE.

Импортёр `tools/migrate.py` (M3): DRY RUN (проверки и план номеров) → MIGRATE COPY (резервная копия; перенос в копию книги целиком или никак; перестройка индекса деталей; самопроверка) → VERIFY (сверка с таблицей, SHA-256 таблицы в журнале, оракул) → PROMOTE (только проверенная и не изменённая копия). Остановка при конфликте ЕИ, артикуле детали у нескольких ЕИ, неизвестной единице или месте (П-13), пустом типе без `--default-source`, неверном количестве.

Тип источника каждой строки переноса обязателен: пустой — блокирующая ошибка, строка не считается «Старым складом» молча; тип для всех пустых строк задаётся только явно (`--default-source "Старый склад"`, D-087). Проверка таблицы — `tools/migration_dryrun.py` (dry-run, книга не меняется).

Требование к переносу (D-056): все старые ЕИ — в плотном реестре «Наличие» и записи `_RCV`/`_ORD` для перенесённых строк «Заказов» с ЕИ; NEXT_EI выше любого кода книги. Иначе перенесённые строки будут считаться копиями, а новые номера — конфликтовать со старыми.

Перенос старого листа «Заказы» целиком (M7, выпуск 0.7.1, исправление 0.7.2; правила П-49…П-70 — на утверждении, `CLAUDE_REPORT_M7_PRIME.md` §9, `CLAUDE_REPORT_HOTFIX_072.md` §4) выполняет книга `WMS_LEGACY_TRANSFER.ods` с программой `tools/legacy_transfer.py` (`docs/LEGACY_TRANSFER.md`): CHECK (план без изменений) → BUILD (копия чистой книги-кандидата, операции ядра, самопроверка, оракул, сверка, сохранение и повторное открытие) → VERIFY (отчёт) → PROMOTE (новая папка `WMS_WORK`, `CUTOVER_README.txt`). Приход старой строки — операция `LEGACY_RECEIPT` / `LEGACY_RECEIPT_ADD`: позиция `_ORD`, приход `_RCV`, строка «Наличие» с прежним ЕИ и текущим остатком (≤ прихода; израсходованное до переноса — как выданное); отмены — `ORDER_CANCEL` / `ORDER_CANCEL_REST`; специальные приходы старой таблицы — `MIGRATE`; открытые позиции — обычные строки заказа. Так требование D-056 выполняется для перенесённых строк «Заказов». Старые статусы W понимаются по смыслу (D-090: «Ожидаем», «Размещён», «Ожидает размещения» — открытый заказ; «Получен без документов» — получено, документов нет; «Отменён» — отменено), рабочий статус считается по данным без даты (D-089): `Просрочено` перенос не рассчитывает.

До production:
- dry-run;
- инвентаризация ЕИ;
- максимальный номер;
- дубли;
- конфликты;
- старые детали;
- бумажные выдачи;
- сверка;
- выборочные физические наклейки;
- rollback.

## 32. Производительность

Цель обычной операции ≤ 0,5 с на рабочем ПК.

Облачные P1–P4 показали большой запас по ежедневным операциям, но скорость открытия/сохранения сильно зависит от железа.

До миграции результат на реальном Ubuntu обязателен.
